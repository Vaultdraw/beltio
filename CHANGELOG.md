# Changelog

All notable changes to Vaultdraw are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Linux packages: `.rpm` for Fedora and an AUR recipe for Arch.** Releases now carry a `.rpm` next to the `.deb` and the AppImage, and `packaging/aur/` holds the `vaultdraw-bin` recipe (the owner publishes it). The packages register the `.excalidraw` and `.excalidrawlib` file types, install icons at 32, 128, 256 and 512 px, the licence and a package description, and each was installed, started headless and removed on Debian 12, Fedora 44 and Arch. One copy-paste install command per distribution is in `docs/linux.md`.
- **Windows installer and CI (not released yet).** A per-user NSIS installer with the WebView2 bootstrapper built in, which also puts the `vaultdraw` command on your `PATH` (removed on uninstall), and a `windows` workflow that tests and builds it on GitHub. The first builds are unsigned, so SmartScreen warns; see `docs/windows.md`.
- **First-run setup.** A new install opens a short, skippable setup, one question per screen: Look (light, dark or follow the system, a theme, an accent, with a live preview), Basics (Vim-style keys in notes, Markdown mode, save speed, line style), Network (Offline mode), Extras (the optional features; the AI assistant stays off) and Vault (open a folder, create one, an Obsidian vault or a recent vault). Every answer is written to `config.toml` as you give it. **Run setup again** is in the command palette; `onboarding.completed` (default `false`) records that it ran, and an install that already has a recent vault never shows it by itself.
- **AI assistant (official plugin, off by default).** Ask a model you choose about your drawing with your own key: **AI: Ask about this drawing**, **Describe the selection**, **Generate a diagram from text** (the answer becomes shapes, one undo step), **Summarise this note**, and **Stop the answer**. Anthropic, OpenAI (or any OpenAI-style address) and a local Ollama; provider, model, address and timeout in Settings, Plugins. A panel streams the answer and **Show what is sent** lists exactly what leaves the app. The key is kept outside `config.toml` and your vaults and cannot be read back. Offline mode blocks it, except a model on this computer. No Vaultdraw server is involved. Plugin API 1.1.0 (experimental additions): `ctx.net` (permission `net`) and `ctx.secret` (permission `secret`); official plugins can now be off by default.

### Changed

- **Narrow windows: the file list opens over the drawing.** Below `[layout] narrow_width` (now 600 px by default; 0 turns it off) the file list folds and Toggle navigator opens it as an overlay on the right; Esc, a click outside it or opening a file closes it and focus returns to where it was. At 360 px the tabs and toolbars now have the whole window.

### Fixed

- **Plugin tool: `vaultdraw-plugin check` agrees with the app on `min_api` and warns on deprecated names.** A `min_api` newer than the plugin API the tool knows (1.2.0) is now an error (`min-api-unsupported`), as the app refuses to load such a plugin; the toast option `action` and `ctx.manifest.dir` in the code give a `deprecated` warning, as the stability promise says. The plugin getting-started guide uses a shell function that works in zsh (toimprove 250, 253, 255).
- **A long note with no blank line opens at once.** A pasted log or CSV of 8,000 lines with no empty line took 7 seconds to show in the reading view (and grew four times slower for twice the text); it now takes about 0.1 second. The rendered result is unchanged.
- **A note with old-Mac line ends (a lone CR) can be ticked.** Clicking a checkbox in the reading view did nothing in such a note. The note keeps its own line ends when it is saved.
- **The external-AI switch is named "External AI tools" in the palette.** The commands read **External AI tools: Toggle AI access** and **External AI tools: Toggle the AI tools interface (MCP)** and **External AI tools: Copy the AI app setup**, so they are not mixed up with the AI assistant's "AI:" commands. The command ids are unchanged, so existing key bindings still work.
- **The Graph's local graph key is ⌘⌥O (Ctrl+Alt+O on Linux), not ⌘⌥L.** Ctrl+Alt+L is the lock-screen key on KDE, Xfce and Cinnamon, so the key never reached Vaultdraw there. Change it in Settings → Hotkeys or `[hotkeys]`.
- **Escape closes Excalidraw's own dialogs after a click inside them (Linux).** In the image export dialog a click left the focus on the page behind it (the button is disabled while it works), so Escape did nothing; Escape on the page body now closes the top dialog.
- **Opening an imported note no longer downloads a web page again.** A link that is not a picture ("Web page, not a picture"), is over 10 MB or was refused is not fetched a second time when the note opens; **Download images** still tries again on request.
- **`vaultdraw ls | head`** and other pipes that close early end quietly instead of printing a "Broken pipe" panic.
- **Fedora: uninstalling the `.rpm` leaves no folders behind** in `/usr/lib/Vaultdraw`.
- **Escape closes Settings when a button or switch inside it has focus.** The editor underneath had already marked the key handled, so Settings stayed open (seen on Linux, where a click focuses the control; Tab does it everywhere).
- **Linux CI:** the Linux workflow runs typecheck, unit tests, `cargo test`, the end-to-end suite (three shards) and the bundles in parallel jobs; the end-to-end tests use the system's own copy, paste and select-all keys in text boxes.
- **Narrow window: the file list overlay behaves like Obsidian's drawer.** Picking the drawing that is already open closes it, renaming the open drawing keeps it open, and one Escape in its search box clears the query and keeps the list (the next Escape closes the list).
- **A picked text colour on a heading now sticks on every path.** Paste styles and the eyedropper used to leave a heading in the theme's colour; and a heading made plain text and a heading again no longer keeps an old pick forever.
- **Narrow window: closing the file list overlay no longer hides the list in a wide window.** The overlay is now a state of the narrow window only, so widening brings the docked list back (toimprove 247).
- **The narrow-window file list takes its shadow and backdrop from the theme.** They were fixed black values a theme could not restyle; they now use the same tokens as menus and dialogs (toimprove 273).
- **The graph plugin's search matches accents like the app's search.** `ß`, `ø`, decomposed accents and the other look-alikes now fold the same way as the quick switcher, because plugins can call the app's fold (`ctx.text.fold`, plugin API 1.2, experimental; the graph plugin needs `min_api 1.2.0`). One copy of the fold now serves the app and plugins (toimprove 197 family).
- **The Rename tag picker ignores accents and case like the rest of search.** Typing `cafe` finds `Café`, `strasse` finds `Straße`, and a decomposed `é` works (the filter used lower case only; toimprove 201 family).
- **A task with a tab after its box is a task in the reading view.** `- [/]<tab>doing` was plain text there (and its box could not be ticked) although the import counted it; a tab now counts as the space, as in Obsidian.
- **The hang watchdog keeps its web view alive (macOS).** It now holds a reference to the main web view and lets go when the window is destroyed, so a re-check can never touch a freed view (toimprove 243).
- **"Insert as table" after a paste no longer removes your own text.** When the table paste was typed into an existing text box, the button replaced that text; it now swaps only the text the paste created.
- **A favourite of a deleted element says so.** Opening it used to show the drawing and do nothing; now a notice reads "That element is no longer in the drawing".
- **A table copied with old-Mac line ends is pasted as a table.** A spreadsheet or CSV copy that separates rows with a lone carriage return was one long row and pasted as plain text.
- **Offline mode and the safety checks also cover the browser-only download path** (theme install, themes and plugins lists): Offline mode, https only, no private or local addresses, redirects checked. The desktop app never used this path; Rust does its downloads.
- **A drawing embed with a size reads as the drawing's name.** `![[Sketch|500]]` showed a link reading "500"; Obsidian reads `|500` as the width, so the link now reads "Sketch" (toimprove 275).
- **A footnote used only inside another footnote is listed.** Its number used to lead to nothing; it now appears in the footnotes list (toimprove 276).
- **Save as template on an Obsidian drawing offers the drawing's name.** It offered "Plan.excalidraw.md"; it now offers "Plan" (toimprove 277).
- **Cmd+Z in a Markdown-mode box after a heading brings back a word you deleted.** After Enter on a heading, typing a word and deleting it, Cmd+Z jumped back to the heading and lost the word; once anything is typed in the box, Cmd+Z is the text box's own undo (toimprove 263).
- **A Markdown link inside an embedded note opens the file next to that note.** It resolved from the note that held the embed, so `[plan index](index.md)` in an embedded `Projects/Plan.md` opened `Inbox/index.md`; links and `[[#Heading]]` links now follow the note that wrote them (toimprove 259).
- **A note's properties are listed in the note's order.** They were alphabetical (`title, date, author` showed as `author, date, title`); the reading view now keeps the file's order, as Obsidian's properties panel does (toimprove 281).
- **The AI assistant sends a saved key only to the service it was saved for.** One key was used for every provider, so an Anthropic key went to OpenAI after switching the provider, or to any address typed into Address. A key is now kept per provider and address, and a different one asks for its own key (toimprove 272).
- **The AI assistant keeps a question it refused to send.** With no key, in Offline mode or on an empty drawing, the question vanished with the refusal; it now stays in the box (toimprove 270).
- **The AI assistant's Copy says it copied** (or that it could not), like every other copy in the app (toimprove 271).
- **The AI panel's checkbox follows the theme colour** instead of the system green (toimprove 284).
- **A code box changed back to a normal font loses the code colour.** It stayed in the theme's code colour; the code role now ends when the font is no longer the code font (toimprove 264).
- **`vaultdraw://new?path=` on an existing note or Obsidian drawing opens it** instead of creating a stray `….excalidraw.md.excalidraw` file next to it (toimprove 265).
- **Template picker and tags panel order names like the file tree.** "Meeting 10" came before "Meeting 2" there; both now use the tree's natural order (toimprove 261).
- **A one-line link is underlined only as wide as its text,** also in a box the user made wider (it was underlined across the whole box, with a link strip over empty space) (toimprove 258).
- **The plugin browser does not offer an update that needs a newer Vaultdraw.** Update and Install are off, with a line saying which version to update to, instead of replacing a working plugin with one that will not load (toimprove 251).
- **Delete data on a plugin also removes the keys it saved** (the AI assistant's API key stayed on disk with no way to see or remove it), and different code installed under an old plugin id no longer inherits them (toimprove 279).
- **`network.allow_ai` is documented,** and the message the AI assistant shows when it is off names it and says what to do; it said "turned off in Settings" although no Settings switch exists (toimprove 278).
- **In a narrow window a plugin side panel floats over the drawing** like the file list (it docked at full width and left the drawing 123 px at 480 px); Esc or a click on the strip of drawing beside it closes it (toimprove 285).
- **A task inside an embedded note can be ticked** and is saved in that note's own file, as in Obsidian; it was a greyed, dead box (toimprove 267).
- **Privacy wording is honest about the network.** The AI switch and its warning no longer say the device is "fully offline" or that Vaultdraw "makes no network requests" (the network is on by default); they point to Offline mode (toimprove 286).
- **User text uses the platform's own words.** Linux no longer says "Cmd" or "Finder": the read-only messages, the tab setting, the AI panel's undo hint and the reveal command (now "Reveal drawing in file manager") say Ctrl and file manager there (toimprove 287).
- **A big note opens at once.** A 1 MB note froze the window for 8 to 14 s (a 4 MB one never opened) because every block rescanned the rest of the note; it now looks only to the end of its paragraph, with the same output (toimprove 288).
- **Pickers and searches find each word in any order, with accents folded.** The vault search's folder and name matches, the theme pickers, the plugin browser and Settings search now share one rule ("2024 work" finds "Work 2024", "cafe" finds "Café"), as in Obsidian and Zed (toimprove 246).

## [0.2.0] - 2026-10-28

The plugin platform (plugin API 1.0, frozen after an audit), Markdown notes with Obsidian vaults, Linux builds and memory work. See [RELEASE-NOTES.md](RELEASE-NOTES.md).

### New

- **A clearer name-clash message.** Renaming or moving onto a name that differs only in capitals or accents now says which file is in the way ("A file named 'été.excalidraw' already exists here (names that differ only in capitals count as the same)"), and dragging in the tree refuses that drop before you let go, with the same Unicode-aware comparison as the backend.
- **A drawing locked while it is open switches to view mode.** If a save is refused because the file became read-only, the drawing shows the read-only banner (now saying how to fix it in Finder) with **Save a copy**, and your edits stay in the window. The quit dialog offers **Save a copy…** for such a drawing.
- **Quit and vault switch ask the same way about unsaved notes.** With `notes.autosave_ms = 0`, switching vault now asks (Save and Switch / Don't Save / Cancel) like quit does, and both dialogs name the notes. A note that cannot be saved stops the switch before your drawing closes, with a message naming it. At quit, every save (drawing, notes, library, plugin data) runs on its own, so one failure no longer skips the others, and Discard and Close names only what failed.
- **A startup notice for plugins waiting for review.** When an enabled plugin is off until you review it (never confirmed, or an update added a permission), one toast at launch names it with a **Review** button that opens Settings, Plugins. The same notice names plugin folders refused for reusing an official plugin id. After this update, plugins you added yourself ask once before their first run (the confirmation record did not exist before). A damaged `plugin-consent.json` is now moved aside as `plugin-consent.json.corrupt` and the notice says so, instead of silently holding everything. Once per launch; the plugin row now says it stays off until reviewed.
- **Linux: no more silent loss of file watching.** When a big vault passes the system's inotify watch limit (`fs.inotify.max_user_watches`), Vaultdraw now polls the vault instead of running with no watcher, and shows one notice on open that says how to raise the limit. `files.watch_poll_ms` (default 5000, 500 to 600000) sets the interval and is only read if the fallback is needed. macOS is unchanged. See [Large vaults on Linux](docs/configuration.md#large-vaults-on-linux).
- **Read-only drawing files open in view mode.** A drawing whose file has no write permission (or is Locked in Finder) opens read-only with a banner, "Read-only file: make it writable to edit", and a **Save a copy** button (the same `file.saveCopy` command), instead of letting you edit and then refusing the save. The open already knows: the native read marks the file, at no extra cost. Make it writable and the banner and view mode lift by themselves.
- **Low-memory canvas (opt-in).** `memory.low_memory_canvas = true` (Settings, Interface, Memory) backs the editor canvases with CPU memory: with three small drawings open the packaged app peaks at about 365 MB instead of about 470 MB, at the price of panning at about 60 frames per second instead of about 120. Off by default; read when the editor starts: Settings shows **Restart now** while the saved value differs from the running one (command `app.restart`, "Restart Vaultdraw"). Also adds `perf/run.mjs --owner-typical` (the simultaneous whole-app memory peak). See [Memory](docs/configuration.md#memory).
- **Vault backup and restore.** `Vault: Back up vault…` (also Settings, General, Backup) writes `<vault> backup <date>.zip` of your drawings, notes and attachments (optionally the vault's settings and history) to a folder you pick: streamed in the background with progress and Cancel, and verified by re-reading the zip and comparing a SHA-256 per file. `Vault: Restore from backup…` extracts into a new folder only, then offers to open it as a vault. `[backup] every = "daily"|"weekly"`, `folder`, `keep` schedule it and prune only the backups this feature made (off by default, no thread until on). CLI: `vaultdraw backup [--to <dir>]`, `vaultdraw restore <zip> <dir>`, no app needed. See [Backups](docs/configuration.md#backups).
- **Several libraries (library management).** Every `.excalidrawlib` file is its own section in the library panel: `libraries/` in the config folder, `.excalidraw-vault/libraries/` in a vault, and any folder in `[library] folders`. Fold sections, create, rename and remove libraries (remove keeps the file in a `.removed` folder), move items between them and import a file into a chosen one. The existing `library.excalidrawlib` stays as **Personal**, no migration. `[library] default` picks where new items go. Palette: `Library: New library`, `Library: Rename <name>`, `Library: Remove <name>`, `Library: Import file into <name>`; `Insert: <item>` searches every library. Files changed outside the app reload live. See [Library](docs/configuration.md#library).
- **Vaults in iCloud Drive, Dropbox, Syncthing or OneDrive.** Conflict copies (`name (conflicted copy …)`, `name.sync-conflict-…`, iCloud's `name 2`) show in the file tree with a `conflict` badge (`sync.conflict_badge`); the row menu's **Compare with original…** and the commands `sync.compareWithConflictCopy`, `sync.keepThis`, `sync.keepOther` open the two versions side by side and keep one: the other goes to the file's History and the copy to the Trash, never deleted. iCloud files that are not downloaded yet (`.name.excalidraw.icloud`) show as `not downloaded` instead of being read as empty; a click asks iCloud to fetch them (`sync.download_placeholders`). Temporary and partial files (`~$x`, `x.tmp`, `.syncthing.*`, `x.sb-…`) stay out of the tree, the search index and the watcher. See [Sync services](docs/configuration.md#sync-services).
- **Opening an official plugin's panel first works.** The Favourites activity bar button now starts the plugin host when the panel is opened before any plugin command ran; before, the panel stayed empty.
- **Focus mode: `view.focusMode`, Esc to leave.** One toggle (Cmd/Ctrl+Shift+Enter, the editor's main menu, the palette) hides everything but the canvas and the drawing toolbar. `[focus] hide` picks the parts (the new `status_bar` is one), `remember` reopens in focus mode, `hint` shows a small `Focus` chip. Esc (`view.focusMode.exit`) leaves it. `layout.preset.focus` keeps working but lost its default key. See [Layout and focus mode](docs/configuration.md#layout-and-focus-mode).
- **Table (official plugin).** Paste spreadsheet cells, CSV or a Markdown table and a toast offers **Insert as table** (`[plugin.table] on_paste = "ask"`, `"always"` or `"never"`); the palette command **Insert table from clipboard** does it from the clipboard. The table is an ordinary group of rectangles, lines and text, in your current stroke and font, columns sized to content with wrapping at `max_col_width`. Plugin API 0.28.0: `ctx.clipboard` (`readText`, `onPaste`; permission `clipboard`; activation `onPaste`), `ctx.scene.currentTextStyle()` and toast action buttons.
- **Favourites (official plugin).** Bookmark drawings, notes and single elements from the file tree or tab menu, `Mod+Alt+J`, or the palette; a side panel lists them in your order (drag or `Alt+Up` / `Alt+Down` to reorder, `F2` to rename, `Delete` to remove); `favourites.open1` to `open9` jump to the first nine. Stored per vault in the `[favourites]` table of `settings.toml` (plain TOML) and kept in step with renames, moves and deletes, also those made before the plugin first loaded in the session. Off with `plugins.disabled = ["favourites"]`; off or unused it costs nothing.
- **Auto-export (official plugin, off until you turn it on).** `[plugin.auto-export] enabled = true` (Settings, Plugins, Auto-export) writes an SVG and/or PNG copy of a drawing after each save, next to it or into an export folder that mirrors your folders (`formats`, `scale`, `background`, `theme`, `folder`). Exports are debounced and rendered one at a time in idle time, never inside the save; they follow a rename (`on_rename`) and a delete (`on_delete`); a folder list (`exclude`) and a `#no-export` text in a drawing (`skip_tag`) opt out. Palette: `auto-export.export-all`, `auto-export.export-current`. Plugin API 0.27.0 adds `ctx.vault.exports` (`render`, `move`, `remove`; `.svg` and `.png` only, never under a dot folder). See [Auto-export](docs/configuration.md#auto-export).
- **Profiles.** A named folder of settings, keys, theme and extensions (`profiles/<name>/config.toml` and its own `overrides.toml`) layered over your `config.toml`; the default is your existing config, so nothing migrates. Switch live from the palette (`profile.switch`, `profile.new`, `profile.duplicate`, `profile.delete`), Settings, General, Profile, `vaultdraw profile list|use|new|duplicate|delete`, `vaultdraw --profile <name>` or `VAULTDRAW_PROFILE`. A vault can name its profile (`.excalidraw-vault/profile`). See [Profiles](docs/configuration.md#profiles).
- **Community plugins registry (backend).** `network.allow_plugins` (asked once, revocable), `plugins.registry_url` and `plugins.registry_ttl_hours`. The app can fetch and cache a plugins `index.json` and install a package from it: the zip must match the list's SHA-256, is read strictly (the rules of `vaultdraw-plugin check`), and its manifest id, version and permissions must match the entry. Format: `sdk/docs/registry.md`. **Settings → Plugins → Browse community plugins…** lists it with search, details and the permissions the plugin declares, and installs, updates and uninstalls (palette: `plugins.browse`, `plugins.browseRefresh`). The default list address points at `Vaultdraw/plugin-registry` (published, empty for now); set `plugins.registry_url` to use another.
- **`[extensions] history`: switch the History panel off.** Hides the panel, checkpoint dialog, History button, activity bar entry and the `history.*` commands. Saving versions stays under `history.enabled` (Settings, Extensions: "File history"), so turning the panel off never stops versions from being kept. On by default.
- **Mermaid is an official plugin.** The `mermaid` plugin owns the Mermaid on/off switch (`[extensions] mermaid` and `plugins.disabled` both work, as before); off means the dialog, the More tools and palette entries, pasting Mermaid text as a diagram and the converter chunk are all gone. New for programs and AI apps: the method `mermaid.to_drawing` (`vaultdraw plugin call mermaid to_drawing '{"text":"graph LR; A-->B","path":"diagrams/flow.excalidraw"}'`, or an AI tool while Settings > AI is on) turns Mermaid text into a new drawing, or into shapes on the drawing on screen. Plugin API 0.23.0 adds `ctx.diagrams.mermaidToElements(text)`, the editor's converter as scene ops, loaded on first use.
- **LaTeX formulas are now an official extension.** The formula code (MathJax, the insert and edit dialog) moved out of the core into the bundled `formula` plugin. Commands (`Formula: Insert formula`, `Mod+Shift+M`; `Formula: Edit formula`), double-click to edit and the `[extensions] formula` switch work as before. Existing formulas keep working: they are ordinary SVG images with their TeX under `latex`, so a drawing opens and shows them even with the extension off. Off, MathJax never loads and notes show the TeX source of `$…$` instead of the picture. An edit redraws the formula on the same element (one undo step): its id, stacking order, group and bound arrows stay.
- **Plugin API 0.24.0.** `ctx.math.render` / `ctx.math.provide` (the TeX renderer the notes view and other plugins share), `ctx.scene.selection()`, `ctx.scene.currentStrokeColor()`, and `ctx.overlays.open(component, { modal: true })` for dialogs that leave the drawing visible. See `sdk/docs/surfaces.md`.
- **PDF import is now an official extension.** It ships in the app, stays on by default and switches off in Settings, Extensions (`[extensions] pdf-import = false`): off, its command, main menu item and picker entry are gone and no code loads. Same dialog, page ranges, settings (`[pdf_import]`) and result (locked pictures, one undo step); dropped `.pdf` files up to 128 MiB still work. The command `file.importPdf` is now `pdf-import.import` (rebind a key you had set on the old id). Drawings that already hold imported pages are unaffected. The dialog now opens over the drawing area (an overlay), and the pages are added when it closes.
- **Plugin API 0.26.0: PDF and page placement.** `ctx.pdf` (permission `pdf`) opens a PDF and renders pages with the app's native renderer (PDFKit, poppler) and reads the `[pdf_import]` settings. `ctx.scene.placePages(sizes)` says where page-sized pictures go in the open drawing (page mode or a column), `ctx.scene.sizeBytes()` gives the drawing's size, and `ctx.scene.batch` takes `pageCount` (set the page count in the same undo step) and `reveal` (scroll the first added element into view). `pdf` is no longer a reserved importer extension: a plugin may import `.pdf`, and `plugins.importers` picks the winner when two do. Docs in `sdk/docs/reference.md`.
- **Plugin API 0.22.0: methods other programs can call.** A plugin declares `[[contributes.methods]]` (needs the new permission `control`) and answers with `ctx.methods.register(name, handler)`: JSON in, JSON out, a timeout, and the plugin loads on the first call. `vaultdraw plugin methods` lists them and `vaultdraw plugin call <plugin> <method> [json]` runs one; the control socket has `plugin.methods` and `plugin.call`. A method with `mcp = true` also appears as an AI tool (`<plugin>__<method>`) while Settings > AI is on and Vaultdraw is running. The test harness gets `callMethod`, and the example plugin `flow-from-text` shows two methods (Mermaid-style text to a flowchart, an element count).
- **Plugin commands from the command line.** `vaultdraw plugin commands [plugin]` lists installed plugins and what they declare (with enabled and loaded state); `vaultdraw plugin run <plugin>.<command>` runs one, loading the plugin on first use. New control methods `plugin.commands` and `plugin.run` (CLI role only).
- **Plugin API 0.20.0.** A command in `plugin.toml` can set `repeat = true` to run again while its key is held. It is used by the graph extension.
- **Plugin API 0.21.0.** `ctx.workspace.openShortcut(path)` returns the key label bound to opening a drawing (it follows the user's own bindings). The graph extension uses it for the shortcut row in its hover card.
- **Plugin API 0.19.0: a plugin's own table in the vault settings.** `ctx.vault.table.read/update` reads and changes `[<plugin id>]` in `<vault>/.excalidraw-vault/settings.toml` (comments and other tables stay). Only plugins that ship with the app may use it, so the graph extension keeps its `[graph]` table as it is today.
- **Copy the AI app setup.** The palette command `AI: Copy the AI app setup (MCP server config)` (`ai.copyMcpSetup`) copies the `mcpServers` entry for `vaultdraw mcp`. `vaultdraw mcp` now also answers JSON-RPC batches, survives a line that is not UTF-8, keeps answering `ping` while a tool call is slow, and reads a modern client's name from each request.
- **Plugin API 0.18.0: the vault graph as bytes.** `ctx.vault.graph.read()` returns the whole link graph in one binary call, and `graph.layout.load/save` keeps a graph view's layout per vault. Needs `vault.read` (and `vault.write` to save). New native command `plugin_call_raw` carries bytes with the same allowlist, permission and consent checks as `plugin_call`, so a graph of 50k notes does not go through JSON.
- **Plugin API 0.20.0: thumbnails and folders.** `ctx.thumbnails` (hooks over the app's one thumbnail service, no extra memory) and `ctx.workspace.useFolder` (sorted, live folder entries) for plugin views that show drawings. Docs in `sdk/docs/surfaces.md`.
- **The Gallery is now an official extension.** It ships in the app, stays on by default and switches off in Settings, Extensions: off, its activity bar button, commands and code are gone and it costs nothing. Same grid, keys and thumbnails (they still come from the app's one thumbnail service). Commands `thumbnails.galleryToggle` and `thumbnails.galleryOpen` are now `gallery.toggle` and `gallery.show-folder`; a saved config list that does not name `gallery` in `plugins.enabled` needs it added. Plugin commands can now declare `repeat = true` in `plugin.toml` (run again while the key is held).

Nothing to declare and nothing loaded until one opens. Example `overlay-demo`, docs in `sdk/docs/surfaces.md`.

The docs include a copyable Vim-style example.
- Settings → Hotkeys has a **Key group names** section for `[keys.labels]`: add, rename or remove the names which-key shows for a group. The config writer now handles the nested `[keys.labels]` table and quoted sequence keys such as `"<leader> f f"`, keeping your comments and order. Existing configs keep working.
- A which-key popup lists what can follow a half-typed sequence. It loads only when a sequence is used. **Keys: show which-key** and **Keys: cancel pending sequence** are in the palette.
- Settings → Hotkeys has a **Sequence** button that records a sequence chord by chord. A key that is the start of another command's sequence shows a `prefix` warning.
- The tool keys (`R`, `E`, `A`, `Q` and the rest) are now commands, `tool.rectangle`, `tool.eraser` and so on, with the same default keys. They can be rebound, removed or turned into sequences in Settings → Hotkeys or `[hotkeys]`.
- `vaultdraw export` no longer sends the image through the control channel as base64. The app writes it to a spool file in 4 MiB pieces and the command moves it to the destination, so big exports no longer hit the 32 MiB limit and the command itself stays at a few MB of memory (32 MiB export: 95 MB -> 3 MB peak). The no-overwrite rule is unchanged.
- **Settings → Plugins** lists installed plugins. You can turn each one on or off, install one from a folder, reload or uninstall it, and edit the settings it declares. Each plugin shows its activation time and a memory estimate. A plugin that isn't bundled asks for consent before it runs.
- **Plugin safe mode:** after two launches in a row crash with plugins enabled, the next launch loads no plugins and says why. Holding Option at launch does the same. The palette commands **Plugins: Restart in safe mode** and **Restart normally** switch between the two.
- **Dev reload:** a plugin with `dev = true` in its `plugin.toml` reloads when its files change.
- Palette commands: **Plugins: Open plugin settings**, **Install from folder…** and **Reload plugin list**.
- New palette command **Plugins: Open plugins folder** (`plugins.openFolder`) shows the plugins folder in your file manager.
- Only the first 6 plugin panel buttons show in the activity bar. The palette or Settings → Interface shows the others.
- A plugin can declare `permissions` in `plugin.toml` (`vault.read`, `vault.write`). The enable dialog lists them in plain words, and the app remembers what you confirmed. An update that adds a write permission is switched off until you press **Review** in Settings → Plugins; an added read permission loads with a notice. A permission is a declaration, not a sandbox: plugins still run with full access. See `sdk/docs/permissions.md`.
- Plugin API 0.9.0: an arrow in `scene.batch` can bind to an element already on the canvas with `start`/`end: { id }` (a rectangle, ellipse, diamond, image or free text), as well as to one added in the same batch with `{ ref }`. The arrow is drawn between the outlines and bound as if you had drawn it, so moving the shape moves the arrow; one undo removes the arrow and both bindings. `vaultdraw scene apply` and the AI tools' `edit_drawing` share the same rules, so they accept `{ id }` too. See `sdk/docs/reference.md`.
- Plugin API 0.8.0: `ctx.markdown.parse` (the app's Markdown parser: a note's blocks, links, tags and stats), `ctx.text` (`measure` and `lineHeight`, the editor's text widths), `ctx.fonts.ensure` (load fonts before measuring) and `ctx.pages` (`geometry` and `flow`, page sizes and pagination). CodeMirror 6 (`@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/commands`, `@lezer/common` and `@lezer/highlight`) is shared with plugins and loads on first import. See `sdk/docs/reference.md`.

Pictures are hashed (SHA-1) and stored once; a batch that would take the drawing past 90% of its 32 MiB cap is refused with `TOO_LARGE`. Arrows cannot bind to images. See `sdk/docs/reference.md`.
- Plugin API 0.6.0: `ctx.vault` lists folders (`list`), reads drawings (`readDrawing`), creates drawings (`createDrawing`, create only) and shows the vault's name and read-only state (`info`). Reading needs `vault.read`, creating needs `vault.write`. See `sdk/docs/reference.md`.
- Plugin API 0.6.0: `ctx.workspace` opens a drawing (`open`, optionally in a new tab) and gives the open drawing's path (`activePath`). Both are free.

The plugin loads only when a matching file is dropped on a drawing or picked in **Import: File…**. An import is one undo step. See `sdk/docs/importers.md`.

- Plugin API 0.4.0: `scene.batch(ops, { path })` applies only if that drawing is still active; otherwise it refuses with `DRAWING_CHANGED`.
- Plugin API 0.4.0: new element properties `angle`, `strokeStyle`, `fillStyle`, `roundness`, `fontFamily`, `link` (`javascript:`, `data:`, `vbscript:` and `file:` refused) and `locked`.
- Plugin API 0.4.0: scene refusals carry a `code`: `NOT_FOUND`, `READ_ONLY`, `DRAWING_CHANGED` or `INVALID_ARGUMENT`. Plugins can check `ctx.host.has("scene.path")` for the 0.4.0 batch additions.

- **Import: File…** accepts the file types that plugins import, as well as PDFs and images.

### Markdown notes and Obsidian

- **Re-import a note from its Markdown.** An imported drawing can be rebuilt from the note it came from, with what the import draws today (real tables, kept line breaks, pictures in place, web pictures downloaded): **Markdown: Re-import this note from its Markdown** (palette, and **Re-import from its Markdown** on a drawing's or tab's menu) for one note, edited or not, and **Markdown: Re-import unchanged imported notes** (whole vault, or **Re-import unchanged imported notes here** on a folder's menu) for every import nobody changed since; changed ones are left alone and counted. It asks once per session for the Obsidian vault the notes came from. Every rewritten drawing is kept in History first; Restore brings it back. Plugin API 0.33.0: `ctx.vault.replaceDrawing`.
- **Update imported notes.** Notes imported by an older version (white page in the dark theme, hand-drawn font) can take your theme and font: the palette command **Markdown: Update imported notes to my theme and font** for the whole vault, or **Update imported notes here** on a folder's menu. Opening such a note offers it once, with **Download pictures** for web pictures left as boxes (asks before any download). Each changed note gets a history version first; your own drawings are never touched. Turn the offer off with `offer_update` in `[plugin.markdown-import]`.
- **Re-import never swaps a note's pictures for "not downloaded" boxes.** When web pictures cannot be downloaded (Offline mode, no connection) and the drawing already has pictures, the note is left as it was and the notice says so.
- **Type `**Bold**` or `` `code` `` in Markdown mode and it renders**. A text box that is entirely `**bold**` turns bold when you type the closing `**`, and one that is entirely `` `code` `` turns monospaced at the closing backtick; the marks go, like the import's all-bold paragraphs. Cmd+Z brings the marks back. New **Markdown: Toggle bold** (Cmd+B, rebindable) bolds the edited box or every selected text. `markdown.inline_styles = false` turns the typing off. Bold or code words inside a sentence need mixed fonts in one text and are planned separately.
- **A paragraph, list or table cell written entirely in bold is drawn bold.** The Markdown reader (and the plugin API, 0.37.0: `marks`, `headerMarks`, `rowMarks`) now keeps bold, italic and code spans instead of dropping them, and the import uses them: `**all of it**` takes the bold font; bold words inside a sentence stay regular (one text, one font). `bold_text` in `[plugin.markdown-import]` turns it off.
- **Bold headings.** Imported notes and headings you type in Markdown mode are drawn in a bold variant of the text's font (Excalifont, Nunito, Cascadia and the others get one; Lilita One is heavy already). `heading_bold` in `[plugin.markdown-import]` and `heading_bold` in `[markdown]` (Settings → Drawing) turn it off. A bold text stores the font id of its family plus 100; excalidraw.com does not know it and shows such text in its fallback font. Plugin API 0.36.0: `bold` on page text items and `ctx.text.measure` fonts.
- **Imported and typed headings look the same.** Both are drawn in the theme's Markdown colours (`markdown.h1` … `h6`, `link`, `code` in a theme file, else derived from its accents), and a colour you pick on a heading is kept.
- **Markdown mode for typing on the canvas.** With it on, `# ` at the start of a line turns the line into a heading as you type (up to `###### `): bigger, in the theme's heading colour. Enter after a heading starts a new text box in normal text just below it; Backspace at the start of a heading makes it normal text; Cmd+Z right after brings the `# ` back. Each drawing has its own switch (the **Markdown** button at the bottom of the canvas, or `Markdown mode: On or off`, Cmd+Alt+M); new drawings follow `markdown.typing`. Lists (`- `, `1. `), tasks (`[ ] `, ticked with **Markdown: Toggle task**, Cmd+L) and quotes (`> `) work the same way; Enter continues a list and ends it on an empty item. Heading sizes and the gap below a heading are in `[markdown]` and Settings. Files stay normal Excalidraw files. See [Markdown mode](docs/configuration.md#markdown-mode).
- **Imported notes are styled by your theme, like Obsidian.** Headings take a colour per level from the active theme, and so do links, code boxes and a new bar on the left of quotes. Switching themes or light and dark restyles every imported note at once. Themes can set these colours in a `markdown` block (`h1` … `h6`, `bold`, `italic`, `link`, `code`, `code_bg`, `quote_bar`, like Obsidian's `--h1-color`); a theme that sets none gets them from its own accent and text colours. The built-in themes set them all, and plugins and CSS snippets can read them as `--vault-md-*`. Headings step down in size like Obsidian's. Turn heading colours off with `heading_colors = false` in `[plugin.markdown-import]`. "Update imported notes" gives older imports the same styling. A colour you pick yourself is kept.
- **Markdown mode: Cmd+Z right after Enter on a heading takes the Enter back**, as in Obsidian: the empty box goes and the caret is back at the end of the heading, like Backspace.
- **Markdown mode: Enter after a heading in a group keeps the next paragraph in the group**. Moving, copying or deleting a grouped card now takes the text typed after its heading along.
- **Page mode: text that runs past the bottom of a page flows to the top of the next page**. Enter after a heading near the bottom of a sheet used to pull the new text up over the heading. Shapes, and text on the last page, are still kept inside the page as before.
- **Custom task statuses are tasks in the import and the note editor too**. `- [/] doing` was imported onto the canvas as the text "[/] doing" and not marked in the note editor; any one status character is now a task everywhere, as in the reading view and Obsidian.
- **Front matter is found the same way everywhere**. A properties block with a blank first line was hidden in the reading view but its tags were missing from the properties, the tag pane and tag search; a block after a leading blank line showed as text while its tags were indexed. The parser now reads front matter by the same rule as the reading view, as Obsidian does.
- **A box typed as `` `code` `` takes the theme's code colour**. It now carries the `code` role like imported code, so `markdown.code` in a theme applies; Cmd+Z brings the marks and the plain colour back.
- **`# **Title**` turns the heading bold when headings are not bold**. With `markdown.heading_bold = false`, closing the `**` used to drop the marks and leave the heading regular.
- **Cmd+B, Cmd+L and Cmd+Alt+M typed in a search box or dialog leave the drawing alone**. The Markdown format keys now act only while the canvas or its text editor has focus; the command palette still runs them.
- **The note editor marks as tags exactly what the tag pane lists**. Colours like `#1e1e1e` are no longer coloured as tags while you write a note, and the `#` suggestions use the same tag characters as the pane.
- **A footnote number scrolls to its own footnote when the note embeds another note with footnotes**. Each embedded note now writes its own footnote and heading ids, so a click in the note never lands in the embed (and the embed's own footnotes still work).
- **`![[Sketch]]` in a note opens the drawing**. Embedding a drawing (`.excalidraw` or an Obsidian `.excalidraw.md`) showed a dead word; it is now a link that opens the drawing. A picture of the drawing inside the note is not drawn yet.
- **Cmd+B flips back to regular with a Lilita One or Assistant text in the selection**. Fonts without a bold face no longer count when Toggle bold asks whether everything is bold already.
- **Cmd+B no longer drops what changed while the bold font loaded**. Toggle bold re-reads the drawing after the font wait, so a shape drawn or a change reloaded in that moment stays.
- **A `[[link]]` or web address in a note's properties is a link**. `up: "[[Projects]]"` showed the brackets as text; the properties panel now shows links you can click, like Obsidian's.
- **Pictures inside an embedded note show**. `![[Other]]` showed Other's text with broken pictures; its pictures, links and deeper embeds now resolve from Other's own folder, as in Obsidian.
- **The lines right under a callout title keep their line breaks**. `> [!note] Title` followed by two lines read as one run-on line; the callout's first lines and footnotes now follow the note's line-break setting like the rest of the note.
- **A callout title shows its Markdown**. `> [!tip] Read **this** and [[Other]]` showed the stars and brackets; bold, code, math and links (wikilinks too) now render in the title, as in Obsidian.
- **Obsidian's custom task statuses show as checkboxes**. `- [/] doing`, `- [-] cancelled`, `- [>] later` and any other single character showed as text "[/]"; they are now ticked boxes that keep their character for themes (`data-task`), and ticking one clears it, as in Obsidian.
- **Tag chips in a note are the tags the tag pane lists**. Colours like `#1e1e1e` are no longer chips that search for nothing, `#tag-` and `#a/b/` read as `tag` and `a/b`, and `"#q"`, `list,#c` and `x:#k` are chips like in the pane; the reading view now uses the same tag grammar as the pane and the search.
- **`$$E=mc^2$$` inside a sentence shows the formula**. It showed the dollar signs; it is now display math on its own line, as in Obsidian. Single-dollar prices stay text.
- **`![[pic.png|caption|300x200]]` keeps its size, and the caption is the picture's alt text**. The reading view now reads the text after `|` with the same parser as the import and the native side.
- **`![[Note#^tbl]]` finds a block id written on its own line after a table, quote or list**. Obsidian's documented form for those blocks showed as an unresolved embed; the embed now shows the block above the id line, and `[[Note#^tbl]]` scrolls to it.
- **A Markdown link in Obsidian's default format opens its note**. `[x](Ideas.md)` for the only `Areas/Ideas.md` (shortest path) and `[x](Areas/Ideas.md)` (path from the vault root) did nothing on click although backlinks listed them; they now open like in Obsidian, through the same link resolver as backlinks. A `./` or `../` link still opens only that file.
- **Vim keys in notes: `:w` saves the note you are in**. With two notes opened, `:w` in the second one saved the first; each note editor now carries its own save, as Vim writes the current buffer.
- **A copied Vaultdraw link of a note or an Obsidian drawing opens it**. `vaultdraw://open?file=Ideas.md` opened `Ideas.md.excalidraw` and said "No such drawing"; a `.md` path now opens as written, and a name without an extension still opens the drawing.
- **A `%%comment%%` or `$$` in the middle of a line no longer splits the paragraph, and the checkbox below ticks its own task**. The reading view showed "Text %%private%% more" on two lines, and in such a note ticking the first task saved a later one; comments, display math and footnote definitions now begin only at the start of a line, as in Obsidian.
- **A long word no longer makes a note's reading view scroll sideways, and sized images keep their shape**. Paragraphs, inline code, headings, lists, tasks, quotes, table cells and links wrap long words, hashes and paths as in Obsidian (code blocks still scroll inside their box); an image with a width and height shrinks proportionally in a narrow note instead of being squashed.
- **The note reading view reads like Obsidian**. A single newline is a line break (new `notes.strict_line_breaks`, off, is Obsidian's setting), `%%comments%%` and trailing `^block-ids` are hidden, and `[^1]` footnotes become numbered links with a list at the end.
- **Every checkbox in a note ticks, even when the note holds a task-shaped example**. An example in indented code, an HTML comment or a math block used to make every checkbox refuse ("Couldn't match that checkbox"); positions now come from the reading view's own parse.
- **Enter or Backspace on an imported heading gives the note's body size**. The import now remembers each heading's body size, and older imported headings are divided by the import's own steps (1.8, 1.6, 1.4, …) instead of the typing defaults, so h1 from a 16 px note gives 16 px, not 14.5.
- **`![alt|100](pic.png)` is sized in a note's reading view,** as in Obsidian (`|100x50` sets width and height too); it used to keep `alt|100` as the alt text at full size.
- **A plain Markdown link to a note works in the reading view.** `[text](Other.md)`, `(My%20Page.md)` and `(Folder/Other.md#Heading)` (what Obsidian writes with Wikilinks off) open the note, Cmd-click opens a new tab; a click used to try to navigate the app window itself.
- **An empty properties block (`---` then `---`) is hidden in a note's reading view,** as in Obsidian (it showed two horizontal rules).
- **Tags and links with ß, æ, œ, ø, ł, đ, ı, kana or Hindi and Thai text match like search does.** The # tag popup found no tag typed with those letters, `[[Orsted]]` did not resolve to Ørsted nor `[[Strasse]]` to Straße, and Hindi or Thai tags lost their vowel and tone marks. One fold now serves the index and the editor.
- **Pasted long text in page mode wraps at the page edge.** Typed text already did; a pasted paragraph used to wrap at up to 800 px and ran past the right edge of an A5, B5 or phone page.
- **Enter and Backspace on a heading give the right body size after you change a heading size.** A typed heading now remembers the text size it was made from, so changing `markdown.h1_size` later no longer makes the next line or the un-headed text the wrong size; an imported heading is read at the default scale.
- **Text no longer runs out of the page or jumps while you type in page mode.** A text typed near the page's right edge used to grow past the page and shift sideways with every key, and ended up wider than the page. It now wraps at the page's edge and stays where it is (Markdown mode on or off).
- **Your text colour no longer turns headings and quotes into plain text.** With a text default colour set (Settings → Tools → Text), Markdown headings and quotes kept that colour and lost the theme's heading colours. They now take the theme's colours; font, size, alignment and line height still come from your defaults, and a colour you pick on a heading afterwards is kept.
- **A typed quote and an imported quote are the same colour** in every theme.
- **Enter after a heading in a shape label** ends the heading: the label goes back to body size instead of every later line being drawn at heading size.
- **A note nested thousands of levels deep no longer crashes the app at every vault open.** Quotes, callouts and lists deeper than 64 levels are read flat, at the 64th level; their text stays.
- **Bold text keeps its bold.** Changing the font of a bold heading in the editor, "Update to my theme and font" and a plugin font change now keep the text bold in the new font; the font picker shows a bold text's font as selected; plugins read a bold text's font by its name.
- **"Re-import unchanged imported notes" no longer brings back a deleted or renamed part.** A long note whose first (or a middle) drawing you deleted, renamed or moved is left as it is and counted as changed.
- **Markdown typing follows Obsidian for lists:** Enter on an empty nested item moves it out one level before it ends the list, and `1. [ ] ` makes a numbered task.
- **"Re-import unchanged imported notes" sees a text box you narrowed, widened or switched to auto size** as an edit and leaves that note alone; it also never creates a drawing (a longer note is named instead: re-import it from its menu).
- **Imported text is no longer cut off at the right edge.** "Update imported notes" now re-wraps text when it gives a note a wider font, and moves what follows down the page (onto a new page when full); running it again repairs notes it already updated. A new import also loads the code font before measuring.
- **Imported notes keep their line breaks and picture order, like Obsidian.** A single line break inside a paragraph stays a line break (the new `strict_line_breaks` key under `[plugin.markdown-import]`, default off, joins the lines instead, like Obsidian's "Strict line breaks"). A picture or embed written inside a paragraph stays where it is written: the text before it, the picture and the text after it are separate blocks in that order, where the picture used to move below the text. Notes imported earlier get this when they are imported again.
- **A web page is no longer taken for an SVG picture** when it has a small inline icon (pasting such a link, or importing a note that points to one, now gives the "not a picture" box instead of a broken picture), and an SVG with a long comment or licence before its first tag is recognised.
- **Re-import unchanged imported notes no longer rewrites notes you edited.** It used to miss moved, retyped, recoloured, resized and trimmed notes. The import now stamps each element it writes; any change you make (move, resize, retype, colour, font, delete, add, link, group, lock, reorder) marks the note as edited and it is left alone. Notes imported before this version cannot be told apart, so a folder or vault re-import leaves them as they are and says so; re-import one from its menu to update it. The re-import commands and menu items also show before the plugin has loaded.
- **A note that got shorter no longer leaves old parts behind.** When a re-import writes fewer parts, each leftover "Name (part N)" drawing that nobody changed goes to the Trash (History keeps it first), and the notice names it; a leftover part you changed is kept and named. Plugin API 0.35.0 adds `ctx.vault.trashDrawing`.
- **Markdown typing: a heading or quote turned back into body text loses its role.** Backspace at the start, Enter on an empty heading and Cmd+Z right after `# ` used to leave the heading role on the text (wrong colour, and the next heading came out at body size). A plugin removing its only data from an element now removes it too.
- **Import Obsidian vault… is on the home screen** while the Markdown import is on, not only in a drawing's main menu.
- **Re-import from a tab's menu rewrites the note of the tab you right-clicked**, not the active one; a picture written as a `data:` address with percent-encoding or extra parameters is read from the address.
- **Imported Markdown tables are real tables, and more notes keep their pictures.** A table is now a grid: a shaded header row, borders, columns as wide as their content, and cells that wrap (nothing is cut with "…", no stray rule, no row or column limit); the cells are ordinary text you can edit. Pictures written as `![alt](my pics/a b.png)` or `<img src="…">` now load like in Obsidian, a picture is recognised by what the file is (a WebP named `.png` works instead of failing the note), the file nearest to the note wins when two share a name, and pictures resolve even with "copy attachments" off. A box that stays empty now says why ("Web image, not downloaded", "Image not found", "Image over 4 MB"). `![[Note]]` embeds point at the converted drawing.
- **Imported notes follow your theme and font.** A Markdown or Obsidian import used to open as a white page in a hand-drawn font whatever your settings; it now starts like a new drawing (your paper theme, so a dark theme gives a dark page, and your drawing font). The Markdown import `font` setting follows your drawing font by default and can name any font; picture placeholders use the note's font. Drawings created by plugins start with your paper and font defaults too. The editor hint "Option-click to cycle selection" no longer draws its key box over the edge.
- **Obsidian re-import into the vault.** The destination folder is chosen before anything is written: if it already holds files, the import goes to a fresh "<Vault> (import N)" folder, so links never point at an older import (also with a partial overlap).

### Offline mode, downloads and updates

- **Offline mode, one switch for the whole internet.** The network is on by default and nothing asks first. **Settings → General → Offline mode**, the palette command **Offline mode: on or off**, or `network.offline = true` turns every internet feature off (plugin and theme lists and installs, web pictures, the update check); each says why in plain words, and a small **Offline** badge in the header shows the state (click it to turn Offline mode off). No request leaves the app while it is on. The old `network.enabled = false` still counts as Offline mode. `network.allow_themes`, `allow_plugins`, `allow_images` and the new `allow_updates` default to on; an explicit `false` still turns that one download off.
- **A quiet update check.** About fifteen seconds after startup, once per launch, Vaultdraw asks GitHub for the latest release and shows a small notice with **View release** only when it is newer. Never repeated, never in Offline mode. `updates.check_on_startup = false` (or **Settings → General → Check for updates at startup**) turns it off.
- **Paste a picture from the web.** Pasting a picture's address (with or without a file extension), or part of a web page with a picture in it, puts the picture on the canvas, downloaded once and kept in the drawing. A web page's address still pastes as a link or embed. A picture address on a private or local network becomes a box that says it was refused. Same checks as imported pictures; `network.allow_images = false` turns it off.
- **Web pictures in a note's reading view show by default.** `notes.remote_images` is now on (it was left over from the ask-first rule). Pictures load through the app's checked download (public `http(s)` addresses only, picture bytes, 10 MiB); `notes.remote_images = false`, `network.allow_images = false` or Offline mode shows the alt text instead and makes no request.
- **Offline mode stays visible with the header hidden:** the Offline chip moves to a thin strip at the top.
- **A picture pasted from the web lands centred on the screen**, not hanging below the centre.
- **Web pictures in old imports download now.** **Download pictures** (and the notice on opening an imported note) missed the boxes of the oldest imports, which show only the picture's description, so nothing downloaded; addresses without a file extension work too (the bytes decide). A box that stays shows one link icon, not two overlapping ones.
- **Web pictures in imported notes are downloaded, and more local ones are found.** The first import with web pictures asks once, in a native dialog that names the sites (`network.allow_images`; https only, no private addresses, 10 MiB, pictures only); the pictures are then kept inside the drawing and work offline. If you said no, "Markdown: Download web images in this drawing" does it later; a web page that is not a picture stays a labelled box. "Markdown: Attach missing images from a folder…" fills the boxes of a single-file import from a folder you pick. ### Security

- **Downloads go only to allowed hosts.** Theme installs, the community themes list, the plugin list and plugin packages may contact only GitHub's own hosts (`raw.githubusercontent.com`, `github.com`, `api.github.com`, `codeload.github.com`) plus `network.allowed_hosts`. The key is read only from `config.toml`: Settings, `vaultdraw config set` and the page never write it. See [Network](docs/configuration.md).

- **Plugin ids and the list address.** A new plugin cannot take the name of a built-in command group (`vault`, `file`, `view`, `config`, …) as its id, so its commands cannot look built in; plugins already installed under such a name keep working. The native side now reads `plugins.registry_url` itself when it fetches the community list, instead of trusting the address the page sends.
- **Links run only link-callable commands.** `vaultdraw://cmd` links now use an allow list (view and appearance toggles, zoom, focus mode, Settings, back and forward, new drawing, open a drawing) instead of a list of blocked words, so a newly added command is never reachable from a link by default. List an exact id in `control.uri_allow` to make another reachable from a link. A command always asks first, even when listed, and the old block list stays as a second check. The refusal message no longer tells people to edit `uri_allow`. See [Control](docs/configuration.md#control).
- **Plugins: no official ids, and first run always asks.** A community or folder-installed plugin can no longer reuse an official plugin's id (`graph`, `gallery`, `table`, …): the install and the scan refuse it (only a plugin with `dev = true` may stand in for one while you develop). A user plugin that was never confirmed now needs a review before it loads, even when it declares no permission, so a shared profile or config that lists it in `plugins.enabled` cannot switch it on silently; the Settings row says "Needs review" and Review records your answer. Plugins you already confirmed keep working; a plugin you enabled earlier that declared no permission asks once.
- **The community plugin and theme list addresses come from `config.toml` only.** `plugins.registry_url` and `themes.index_url` are no longer read from the Settings file (`overrides.toml`), so nothing in the page can point the list at another GitHub repository; Settings and scripts can no longer write them.
- **Theme install and the command line.** Theme names with invisible or text-direction characters are refused (they could pose as another name); uninstalling a theme removes only the files the install wrote and keeps anything you added to its folder. `vaultdraw export --out-dir --embed-scene` names files `X.excalidraw.png`, like a single export.
- **Exported SVGs no longer carry web addresses from untrusted drawings.** An image whose data was a web address (`https:` and so on) used to be copied into every exported SVG (export menu, command line, auto-export), so opening the SVG could contact that server. Only embedded `data:image/...;base64` images are exported now; any other image stays an empty placeholder.
- **Auto-export no longer overwrites or deletes your own images.** It used to replace any `.svg` or `.png` with the drawing's name (your `Logo.png` beside `Logo.excalidraw`) and delete it with the drawing. It now records the files it writes (name and hash) and leaves everything else alone, with one notice; deleted exports go to the Trash, and a case-only rename moves the export. Exports from earlier versions are not recorded: delete the old file once and the next save recreates it.

### Faster

- The search indexer lists each folder with one bulk directory read on macOS, the same read the file tree uses, instead of one file-system query per drawing: listing 3,000 drawings took about 20% less time in a unit benchmark. A drawing removed while a folder is being listed no longer matters: that folder is listed again one entry at a time.
- Opening a vault shows the file tree sooner on a slow CPU: the home pane now draws one frame after the tree, in the same place (about 10 ms sooner at 4x CPU slowdown). `interface.defer_home_pane = false` draws both together.
- `vaultdraw search` and the first in-app search on a vault with no index are faster on a 5,000-drawing vault: about 240 ms instead of 360 ms at background priority and 10 to 17% faster at normal priority, with 20 to 30% less CPU. The indexer now reads each drawing only up to its elements instead of the whole file with its embedded images, opens files relative to their folder, and reads on up to 8 threads. The index is still stored outside your vault and is still safe to delete.
- Switching between drawings is faster on a slow CPU: the editor now shows the new drawing in one render instead of two. On a 4x-throttled CPU, switching back and forth takes 6 to 12% less time (median) and 11% less at the slow end (95th percentile).
- Opening a vault is a few milliseconds faster on a slow CPU: adding the vault to the recent list no longer makes the settings be parsed and checked a second time.
- `interface.thumbnail_max_elements` in `config.toml` sets the biggest drawing that gets a thumbnail (default 8000, was a fixed 2,500). Changing it applies live.
- **Start file list** (Settings → General → Startup, `files.list_start`, default when idle): the walk of every vault folder that feeds Recent drawings, the file switcher, link suggestions and the move dialog no longer runs at vault open. The file tree still loads at once. "On first use" waits for the first of those.
- **Startup** settings (Settings → General): choose when the search index, link index and file history start: on open, when idle, or on first use (`search.start`, `links.start`, `history.start` in `config.toml`, live reload). Search and links default to when idle, so opening a vault no longer waits for indexing; history stays on open so every edit is versioned.

### Plugin SDK

- **Plugin API 1.0: frozen after an audit.** Every exported name was checked; nothing a plugin could use was removed. A plugin written for 1.0 keeps working on every 1.x app, and changes follow semantic versioning: additions and deprecations in a minor release, removals only in 2.0 (a deprecated name warns once in the plugin log and stays until then). New: `api = 1` in `plugin.toml` (`api = 0` still loads, with a warning), `min_api` (the oldest API revision a plugin needs; an older app refuses it and says why), public `PluginApiError` and `PluginErrorCode` types. Deprecated: `ToastOptions.action` (use `actions`) and `ctx.manifest.dir`. `ctx.thumbnails`, `ctx.vault.graph` and `ctx.vault.table` are tagged `@experimental` and stay outside the promise. A test pins the public declarations, so a change needs a version bump and an entry in the new [API change log](sdk/api/CHANGELOG.md); the promise is in [sdk/docs/stability.md](sdk/docs/stability.md).
- The mock host takes the app's op limit: `boot(manifest, plugin, { sceneMaxOps })` is `plugins.scene_max_ops` (1 to 1000, default 500), applied to `ctx.scene.batch`, imports and `ctx.vault.createDrawing` as in the app. Before, the mock always used 500. The in-repo kit takes the same option. The rules the app's host and the mock share (settings, scene ops, vault paths, importers, feature names) moved from `sdk/api/testing/` to `sdk/api/shared/`; `vaultdraw-plugin init` copies both folders.
- **API revision 0.3.0** (additions only): `ctx.storage.global`, a key-value store of JSON values per plugin (`get`, `set`, `delete`, `keys`), saved in the app's state folder, never in a vault. Nothing is read until first use; writes are batched and flushed before quit. New key `plugins.storage_limit_kb` (default 1024). Settings → Plugins shows each plugin's data size with **Delete data**, and **Plugins: Delete data of a plugin…** (`plugins.deleteData`) opens it; uninstalling keeps the data. Native plugin calls now go through one gateway that checks the declared and confirmed permissions (`PERMISSION`). The mock host and the in-repo kit have `storage` (`data`, `seed`, `setLimitKb`); `check --activate` skips `ctx.storage` with a warning.
- **API revision 0.2.0** (additions only): `ctx.host` (`app`, `api`, `has(feature)`), a read-only `ctx.theme` (`mode()`, `tokens()`, `onChange`), `ctx.manifest.permissions` and the manifest key `permissions`. Feature names for `has` are generated from the `@since` tags; the 41 theme token names are documented in `sdk/docs/theme-tokens.md`. The names `net`, `secret` and `control` are reserved as permissions. `check` reports `permission-*` codes; the mock host and the in-repo kit have `theme.set`.
- `sdk/api`: the `@vaultdraw/api` types package (types only, not published yet).
- `vaultdraw-plugin`: a command line tool with `check`, `init` and `dev`.
- `@vaultdraw/api/testing`: a mock host. `boot(manifest, plugin)` runs a plugin under vitest with a fake scene, event bus, settings and toasts, and enforces the app's rules. `VAULTDRAW_TEST_HOST=mock` runs the example tests on it. See `sdk/docs/testing.md`.
- `sdk/api/plugin.schema.json`: a JSON Schema of `plugin.toml` for editor completion, and a generated manifest reference (`sdk/docs/manifest.md`).
- `vaultdraw-plugin build`: bundles a TypeScript project into `dist/` with esbuild. The entry can be set under `[x-build]` in `plugin.toml`.
- `vaultdraw-plugin package`: checks, then writes `<id>-<version>.zip` (reproducible, flat layout) and a `.sha256` file.
- `vaultdraw-plugin check` accepts a `.zip`: it verifies the checksum, reads the archive strictly and checks the contents (new codes `zip-checksum`, `zip-invalid`, `zip-layout`). `main-missing` suggests `build` when the project has a source entry.
- TypeScript templates: `vaultdraw-plugin init <id> --template command|panel|scene`. `dev` builds a TypeScript project and mirrors `dist/`.
- Dev log: for a plugin with `dev = true`, the app appends its `ctx.log` lines and attributed errors to `<state dir>/plugin-logs/<id>.log` (capped at 1 MB). `vaultdraw-plugin dev` shows new lines, prefixed with `log |`.
- `create-vaultdraw-plugin`: a thin wrapper around `init --template command` (not published).
- `vaultdraw-plugin check --activate`: also runs `activate()` once in a dry host (a child process with a timeout) and reports declared commands or panels that are never bound, undeclared ones, unknown events, errors and endless activations.
- `vaultdraw-plugin dev --sandbox`: starts the app on a throwaway config, state and vault with the plugin enabled, and removes them on exit.
- Doc pages: `sdk/docs/testing.md` and `sdk/docs/packaging.md`.
- A manifest test corpus that pins what `plugin.toml` accepts and refuses.
- Two doc pages: `sdk/docs/reference.md` and `sdk/docs/getting-started.md`.
- A lint (D7): official plugins, built-in extensions and example plugins may import only the public API, never app or editor internals.
- **CSS snippets:** put your own `.css` files in the config folder's `snippets/` and turn each on in **Settings → Appearance → CSS snippets** or with `appearance.snippets` in `config.toml`. They apply after the theme, reload live, and never touch files or exports. Palette commands open the folder, reload, and toggle each snippet (rebindable).

### Changed

- A save reads the drawing once instead of twice when it is older than 100 ms and its file stamp (inode, size, modification time) is unchanged; any doubt falls back to the full second hash. About 3 ms less per save of an 8.6 MB drawing.
- **Plugin loading costs less.** The formula plugin's `main.js` drops from 3.3 MB to 19 KB: the MathJax worker text is a second file (`worker-src.js`) read on the first formula render only. Auto-export loads only while `[plugin.auto-export] enabled = true` (as the docs said). Changes under the config folder's `plugins/`, `themes/`, `snippets/` or a `.git` folder no longer re-read your settings. Waiting for the formula renderer no longer polls every 50 ms.
- **The graph view is an official plugin.** It moved out of the app core into `plugins/official/graph` and runs on the plugin API (overlays, vault graph bytes, own vault settings table). Same commands, keys, behaviour and `[graph]` settings. **Settings → Extensions → Graph view** (or `[extensions] graph = false`) turns it off, and turned off it costs nothing.
- Ten built-in themes instead of 123: Default, Dracula, Catppuccin, Solarized, Gruvbox, Tokyo Night, Nord, Kanagawa, Everforest and One Dark. All ten are in the startup code, so there is no lazy theme loading. The rest moved to the Vaultdraw/themes repo; a `config.toml` that still names one shows Default, with a notice and an **Install it** button. `One` and `Everforest Alt` still select One Dark and Everforest.
- Lower memory at editor start: the interactive canvas shrinks at once when it has not painted yet, and the static canvas takes its laid-out size instead of drawing once at window size. About 12 MB less in the editor page's own peak.
- **No more internet permission prompts.** The question before downloading themes, browsing community plugins or showing web pictures is gone (the native Allow / Don't Allow dialog and the in-app Allow step); the safety checks stay (http or https only, no private or local address, size limits, timeouts).
- **Web pictures just show.** Pictures from the web in an imported note are downloaded during the import, with no question, and the picture boxes of notes imported earlier fill in by themselves when the note opens. `http` addresses work too; private and local addresses are refused, downloads are capped at 10 MiB and checked by their bytes. A box that could not be filled says why, with **Retry**. `network.allow_images` now defaults to on; set it to `false` to keep pictures as boxes. **Network access** off still stops everything.
- **Imported tables move as one and read cleaner.** A Markdown table in an imported note is one group (click selects the table, double-click edits a cell), with a heavier rule under the header like a pasted table. Tables with very many columns stay inside the page instead of running past its edge. Notes imported by an older version keep their old text table until they are imported again.
- **Any key can be rebound, like VS Code and Obsidian.** Keys the system or menu owns (Cmd+Q, Cmd+Tab) and the text keys (Cmd+C, X, V, Z, A) are no longer refused on the Hotkeys page; the row shows what the key clashes with.
- **Settings text and tooltips show your real shortcut** (zoom, focus mode, pens, refresh, save), and follow rebinds and the platform.
- **Every dialog uses one frame.** Template picker, Save as template, Paper settings, Page setup and Rename tag now look and behave like the other dialogs: Escape closes only the top dialog, Tab stays inside, focus returns to where it was, and footer buttons have one height. Discarding a snapshot and reloading from disk now ask once before losing anything; "Keep the original" is shown as a destructive button. The always-disabled "Open in new window" tab menu item is gone. The Import PDF and Formula dialogs from the official plugins use the same frame too, so they follow the same Escape stack (a confirm over them closes alone), Tab order and focus return.
- **Menus, toasts and dialogs stack in a fixed order.** One z-index scale: toasts show above menus and dialogs above both. Reduced motion is honoured everywhere.
- **A cleaner file-tree right-click menu.** Items sit in groups split by dividers (create, organise, copy path, reveal, rename and Move to Trash last), "Copy path" and "Export" open submenus with a chevron, items that open a dialog end in "…", and each item shows its key when it has one. Arrow keys, Home, End, ArrowRight and ArrowLeft for submenus, and typing a name's first letters all work. New commands "List: Copy item path", "Copy item absolute path" and "Copy item link" (no default keys) copy the focused row's path.

### Known limitations

- The macOS build is still unsigned: right-click, Open the first time (or System Settings, Privacy & Security, Open Anyway).
- Linux: x86_64 and arm64 `.deb` and AppImage are built. On a vault past the inotify limit the watcher polls (`files.watch_poll_ms`) instead of staying off.
- Community plugins: the list at `plugins.registry_url` (`Vaultdraw/plugin-registry`) has no plugins yet, so Browse is empty.
- Plugins are new: the API is frozen at 1.0 (see Plugin SDK), but plugins are still young. No automatic update yet.

## [0.1.1] - 2026-10-22

First public release. Vaultdraw is an offline, local-first vault for Excalidraw drawings: pick a folder, and your drawings are ordinary `.excalidraw` files you own. No accounts, no cloud, no telemetry.

### New

**Vault and files**

- Pick any folder on your computer as a vault; drawings and folders are real files and directories.
- File tree beside the canvas to create, rename, duplicate, move and delete drawings and folders.
- Drag and drop in the file tree, and drop Finder files onto the canvas.
- Autosave with atomic writes, plus crash recovery for unsaved work.
- Changes made outside the app are picked up without losing your unsaved edits.
- Navigator sorting by name or modified date, with folders first and numbers sorted naturally ("Drawing 2" before "Drawing 10").
- Optional confirmation before moving a drawing to the Trash, and a default folder for new drawings.
- New folder option in a folder's menu.
- Open several drawings in tabs, with pinning, drag to reorder, and per-vault tab restore.
- Activity bar for the main panels, which you can reorder or hide.
- Gallery view of a folder with thumbnails, and thumbnails for recent drawings on the home screen.
- Visible History, Graph and Library entry points in the header, canvas menu and drawing menus.
- Reveal the crash-recovery folder from the command palette.

**Templates**

- Vault templates in a `Templates` folder and global templates shared by all vaults.
- Template picker with a search box and thumbnails, opened with Cmd/Ctrl+Option+N.
- Save any drawing as a template for this vault or for all vaults.

**Editor and canvas**

- Page mode: draw on simulated paper (A3, A4, A5, B5, Letter, Legal, iPad, Phone or a custom size), in portrait or landscape, as separate sheets or one continuous page. Export the pages as one PDF, or as whole-page PNG or SVG.
- Notebook backgrounds for drawings: plain, grid, ruled lines (with a margin line), dots, graph paper and isometric, with a default for new drawings and a choice per drawing.
- Paper themes for page mode: Normal, Old school (ruled and with a red margin) and Match current theme.
- Insert Mermaid diagrams and LaTeX formulas, both converted offline.
- Import PDF pages as images to annotate them, rendered natively on macOS; password-protected PDFs can be unlocked in the import dialog.
- Drop a PDF on the canvas to open the import dialog.
- Tool defaults: each drawing tool (rectangle, diamond, ellipse, arrow, line, text) can start with its own style, and remembers the last style you used until you quit.
- Text you create by double-clicking, pasting or labelling a shape uses the Text tool's style.
- Drawings can keep their own style choices, with a "Use default" option to go back.
- Pen presets, a configurable laser pointer, and a highlighter.
- Personal and vault libraries that keep their items between sessions, with named items and search.
- Export image dialog for PNG or SVG at 1x, 2x or 3x, with or without background, dark mode, embedded scene or selection only.
- Copy PNG or SVG to the clipboard from the export dialog or the right-click menu; on macOS the image goes to the native clipboard.
- Import file on the canvas right-click menu places images at the point you clicked.

**Search, links and tags**

- Full-text vault search across drawing names, folder paths, text, shape and arrow labels, frame names and formulas.
- Search results grouped by drawing with highlighted snippets; jump straight to the matching element.
- Search ignores case, accents and character width, and finds Chinese, Japanese and Korean text.
- Search index kept outside the vault, rebuilt automatically, and safe to delete.
- Wiki-style links: type `[[Name]]` or `[[Name|label]]` in any text, with an autocomplete list while typing.
- Links are drawn in the accent colour and underlined, with a hover preview of the linked drawing.
- Cmd+click a link to open it, or use link hints (Shift+F) to open one from the keyboard.
- Shape links: attach a drawing to any shape and open it by Cmd+clicking the shape.
- Backlinks panel with backlinks, outgoing links and unlinked mentions.
- Renaming or moving a drawing updates the links that point to it, and a notice reports what changed.
- Drawing shortcuts: give any drawing its own key.
- Graph view of every drawing and link, plus a local graph of the drawings near the open one, with search and filters.
- Tags: a Tags panel, tag chips in the file tree, a tag filter in search, `#` autocomplete, and renaming a tag across the whole vault.

**Themes and appearance**

- Colour themes for the app and the drawing board, each with light and dark variants, plus Light, Dark and System modes.
- Built-in themes including Dracula, Tokyo Night, Catppuccin, Everforest, Gruvbox, Nord, Rosé Pine and Solarized.
- Themes use the Noctalia palette format, so existing Noctalia palettes work; add your own as JSON files in the config folder.
- Sync canvas with theme: recolours the on-screen canvas to match the theme, while saved files and exports keep standard colours.
- Accent colour that replaces the theme's primary colour, adjusted for contrast when needed.
- Whole-app interface zoom from 50 to 200 percent.

**Settings and hotkeys**

- Settings page with sections and search, in the style of Obsidian.
- Plain-text configuration in `config.toml` in a config folder (`~/.config/vaultdraw` on macOS and Linux), edited by hand or in Settings, and reloaded live.
- Comments in `config.toml` are kept when you change a setting in Settings.
- Typos never break the app: the last good settings stay in use and a banner names the line that failed.
- Per-vault settings in `.excalidraw-vault/settings.toml`, with a Global / This vault switch for each setting.
- Hotkeys page to view, add, change and reset the key for every command, with conflict warnings and a key recorder.

**Command palette**

- Cmd/Ctrl+P opens a drawing by name; Cmd/Ctrl+Shift+P runs any command.
- Fuzzy matching, so `vdg` finds `vault-design`; recently used items come first.
- Every feature is a palette command, including themes, modes, settings pages, export, templates and insert actions.
- Tab narrows to a family of commands, and Cmd/Ctrl+Enter runs a command without closing the palette.

**Plugins (experimental)**

- Plugin host for drawing panels and commands from folders in the config folder, enabled through `config.toml`.
- A plugin that crashes is switched off and reported, without affecting the rest of the app.

**Command line `vaultdraw`**

- Install the `vaultdraw` command from the command palette, into your PATH or into `/usr/local/bin`.
- Offline commands to list, read, search, write, create and move drawings, and to show links, tags and settings.
- Commands for a running app: open a drawing and wait for it, list and run app commands, switch tabs, and quit.
- Shell completions and a manual page; `vaultdraw --help` lists everything.

**History and recovery**

- File history keeps earlier versions of each drawing, including versions saved before an outside change or a command-line write.
- History panel with a timeline, previews, thumbnails and highlights of what changed since a version.
- Restore a version as a copy, export it as `.excalidraw`, or create named checkpoints.
- History settings control how many versions are kept and when old ones are cleared.
- Delete a drawing's history, or exclude it from git when the vault is a git repository.

### Improved

- Faster startup and vault opening; features such as settings, history, graph, PDF import and formulas load only when you first use them.
- Lower memory use: caches are cleared when macOS reports memory pressure or when the app has been hidden for a while, and closed editors release their canvas memory.
- Large vaults stay responsive: the search index and link index build in the background, and long folder lists scroll smoothly.
- Saving and opening large drawings is faster on Apple Silicon.
- Smooth zooming and panning, with frames drawn at the display's refresh rate (up to 120 Hz on ProMotion displays).
- The command palette and Settings open instantly, even in large vaults.
- Tab switching is smooth, and switching back to a tab restores its undo history.
- Designed to run well on low-end Macs, with idle drawings using little memory and background work kept small.

### Fixed

- A vault stays writable after the window reloads; if a vault is read-only, the reason is shown and you can try again.
- Moving, renaming or trashing an open folder no longer shows it as missing.
- Undo no longer reaches back into a previous drawing after switching to another one.
- Pen colours and opacity no longer leak into the next tool.
- Text created by double-click or paste takes the Text tool's style.
- Dark-mode SVG images show their colours correctly on macOS.
- Library previews show formulas and images in the on-screen colours.
- Page 1 in page mode sits below the floating toolbar.
- Right-click Reload menu is hidden in release builds, while text fields keep their normal menu.
- The Ctrl-based save, settings and search shortcuts keep working on macOS.

### Known limitations

- The build is unsigned, so the first open needs **right-click → Open** or **System Settings → Privacy & Security → Open Anyway** (see the README).
- Memory: with a typical vault the app peaks around 420 MB while opening drawings (the goal is under 400 MB). Idle use is about 215 MB. Bringing the peak down is the focus of the next release.
- macOS only for now. Windows and Linux builds are not part of this release.
- Plugins are experimental and their interface may change.
- There is no automatic update yet. Check the [GitHub releases](https://github.com/Vaultdraw/vaultdraw/releases) page for new versions.
