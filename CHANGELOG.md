# Changelog

All notable changes to Vaultdraw are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Refresh button and `files.auto_reload`.** The navigator header has a Refresh button (`Mod+Shift+R`, command `navigator.refresh`) that re-reads the tree and the file list. The new `files.auto_reload` setting (default on, Settings > Files, live) turns the file watcher off; then only Refresh updates the tree. See [Files changed outside the app](docs/configuration.md#files-changed-outside-the-app).

### Changed

- **Any key can be rebound, like VS Code and Obsidian.** Keys the system or menu owns (Cmd+Q, Cmd+Tab) and the text keys (Cmd+C, X, V, Z, A) are no longer refused on the Hotkeys page; the row shows what the key clashes with.
- **Settings text and tooltips show your real shortcut** (zoom, focus mode, pens, refresh, save), and follow rebinds and the platform.
- **Every dialog uses one frame.** Template picker, Save as template, Paper settings, Page setup and Rename tag now look and behave like the other dialogs: Escape closes only the top dialog, Tab stays inside, focus returns to where it was, and footer buttons have one height. Discarding a snapshot and reloading from disk now ask once before losing anything; "Keep the original" is shown as a destructive button. The always-disabled "Open in new window" tab menu item is gone. The Import PDF and Formula dialogs from the official plugins use the same frame too, so they follow the same Escape stack (a confirm over them closes alone), Tab order and focus return.

- **Menus, toasts and dialogs stack in a fixed order.** One z-index scale: toasts show above menus and dialogs above both. Reduced motion is honoured everywhere.
- **A cleaner file-tree right-click menu.** Items sit in groups split by dividers (create, organise, copy path, reveal, rename and Move to Trash last), "Copy path" and "Export" open submenus with a chevron, items that open a dialog end in "…", and each item shows its key when it has one. Arrow keys, Home, End, ArrowRight and ArrowLeft for submenus, and typing a name's first letters all work. New commands "List: Copy item path", "Copy item absolute path" and "Copy item link" (no default keys) copy the focused row's path.

### Fixed

- **Import file takes BMP, ICO, AVIF and JFIF** even when the system gives no file type; a full favourites list says it is full instead of "Removed".

- **A 32 MiB drawing fits in one message of the control API and the MCP server.** The message cap is now 80 MiB, so a drawing that grows once it is escaped into JSON is no longer refused; a message over the cap says the limit in plain words.

- **SVG export keeps ICO and JFIF images.** The list of image types an exported SVG may embed is built from the one list of types the editor accepts, so a pasted favicon or a `.jfif` photo no longer becomes an empty placeholder.

- **Auto-export says plainly when a file is in the way.** If a file with the export's name was not made by auto-export (an older export, or a copy a sync conflict left), the plugin leaves it alone and now shows one message per file naming it and saying to delete or rename it, instead of failing quietly on every save.

- **The community plugin and theme list addresses come from `config.toml` only.** `plugins.registry_url` and `themes.index_url` are no longer read from the Settings file (`overrides.toml`), so nothing in the page can point the list at another GitHub repository; Settings and scripts can no longer write them.

- **Notes and Obsidian Excalidraw files can be renamed, moved and moved to the Trash from the file tree**, from the right-click menu, the keyboard and by dragging, like drawings. The extension is kept.

- **New drawings and drawings from a template take the next free name** ("Untitled", "Untitled 1"), like Obsidian, instead of a number from the clock that could clash.

- **A folder deleted outside the app no longer lingers.** After Refresh or coming back to the window, the tree forgets it, and a new folder with the same name starts collapsed.

- **Search stays current when "Reload when files change outside the app" is off.** Saving, moving and trashing in the app update full-text search, and Refresh rescans it.

- **`mailto:` links in notes and on the canvas open your mail app.**

- **A name that is already taken says so** ("A file named “x” already exists here.") instead of "Drawing changed on disk".

- Plugin safe mode (Option held at launch, or "Restart in safe mode") no longer hides the official plugins: the graph view, gallery, frames and Markdown import keep their buttons and commands. Only a safe mode after crashed launches turns them off.
- The Favourites plugin loads again (its manifest asked for app version 0.26.0).
- **Changes made in a file manager now reach the whole tree.** A rescan used to reload only the top level, so a folder deleted, renamed or moved in Finder could stay listed inside an open folder. A rescan now reloads every folder the tree shows, and coming back to the window re-reads them.

- **Web pictures in imported notes are downloaded, and more local ones are found.** The first import with web pictures asks once, in a native dialog that names the sites (`network.allow_images`; https only, no private addresses, 10 MiB, pictures only); the pictures are then kept inside the drawing and work offline. If you said no, "Markdown: Download web images in this drawing" does it later; a web page that is not a picture stays a labelled box. "Markdown: Attach missing images from a folder…" fills the boxes of a single-file import from a folder you pick. A vault whose attachments folder is a link to a folder elsewhere is followed (read only; links into hidden folders or back into the vault are not). New plugin API 0.31.0: `ctx.network`, permission `network.images`.

- **The network consent dialog looks like part of the app.** It now shows the Vaultdraw icon, plain titles ("Allow downloading themes?"), no config keys, and Allow / Don't Allow buttons; the in-app consent messages no longer name config keys either. Settings > General > Config File lays out cleanly: the buttons sit beside the text, the file rows use the full width, and paths shorten in the middle of the folder instead of breaking inside a word.

- **Imported Markdown tables are real tables, and more notes keep their pictures.** A table is now a grid: a shaded header row, borders, columns as wide as their content, and cells that wrap (nothing is cut with "…", no stray rule, no row or column limit); the cells are ordinary text you can edit. Pictures written as `![alt](my pics/a b.png)` or `<img src="…">` now load like in Obsidian, a picture is recognised by what the file is (a WebP named `.png` works instead of failing the note), the file nearest to the note wins when two share a name, and pictures resolve even with "copy attachments" off. A box that stays empty now says why ("Web image, not downloaded", "Image not found", "Image over 4 MB"). `![[Note]]` embeds point at the converted drawing.

- **A view over the drawing area gives way when you open a file.** Open the Gallery or the Graph, then click a file in the explorer, pick one in the quick switcher or search, or click a tab: the view closes and the file shows. It works the same when the file is already the open one, with tabs turned off, and for any plugin view that covers the drawing. **Go back** (`links.back`, `Mod+Alt+Left`) brings the view back once.

- **Graph labels no longer blink.** The graph decided which labels to show again on every frame while nodes drifted, so labels flipped on and off. Labels now fade in and out, keep their place while the layout settles, and stay away for a moment after giving way to a neighbour. The Graph settings are documented in `docs/configuration.md`.

- **Folders with files in them can be moved to the Trash.** "Move to Trash" used to refuse any folder that was not empty. It now moves the folder and everything in it to the system Trash (you can restore it there), closes its open tabs, and the confirmation says how many files it holds. Links inside the folder are moved as links, never followed. "Confirm before trashing" (`files.confirm_delete`) covers folders too.

- **Themes in Settings.** Install Themes now sits right under the theme picker. The Community themes dialog draws the same dark and light mini-window previews as the picker (from the palette, nothing to download), with one short details line per card. "Source" and the other external links now open in your browser.

- **Error notices are small, themed and close by themselves.** Failures (a drawing that can't be saved, moved or moved to the Trash, and so on) now show as a small notice in the corner, like the other toasts, instead of a grey full-width bar that stayed until you closed it. The wording is plain ("Couldn't move \"Notes\" to the Trash: …"). The X, or Esc on a focused notice, closes it; it closes itself after `interface.notice_seconds` (default 8, `0` keeps it until dismissed; also in Settings > Interface), and hovering or focusing it pauses the count. Notices share one design: a short title, an optional detail line, a progress bar with a count, and real buttons. The Markdown import shows its progress that way ("Importing notes", `1719 / 1855`, Cancel) and ends with a short result and a View report button. Plugins get the same design through `ctx.ui.toast` options `detail`, `progress`, `actions`, `id` and `kind` (plugin API 0.30.0).

- **Checkmarks no longer overlap the label** in the canvas right-click menu ("Arrow binding", "Snap to midpoints" and the other checked items).

- **Imported notes follow your theme and font.** A Markdown or Obsidian import used to open as a white page in a hand-drawn font whatever your settings; it now starts like a new drawing (your paper theme, so a dark theme gives a dark page, and your drawing font). The Markdown import `font` setting follows your drawing font by default and can name any font; picture placeholders use the note's font. Drawings created by plugins start with your paper and font defaults too. The editor hint "Option-click to cycle selection" no longer draws its key box over the edge.

- **Theme install and the command line.** Theme names with invisible or text-direction characters are refused (they could pose as another name); uninstalling a theme removes only the files the install wrote and keeps anything you added to its folder. `vaultdraw export --out-dir --embed-scene` names files `X.excalidraw.png`, like a single export.

- **Search finds decomposed Japanese and Korean names and text.** Kana with a separate voicing mark (e.g. か + dakuten, common in file names copied from older Mac disks or zip files) and Korean written as separate jamo now match what you type. The search index rebuilds once on the first launch after the update.

- **Exported SVGs no longer carry web addresses from untrusted drawings.** An image whose data was a web address (`https:` and so on) used to be copied into every exported SVG (export menu, command line, auto-export), so opening the SVG could contact that server. Only embedded `data:image/...;base64` images are exported now; any other image stays an empty placeholder.

- **Auto-export no longer overwrites or deletes your own images.** It used to replace any `.svg` or `.png` with the drawing's name (your `Logo.png` beside `Logo.excalidraw`) and delete it with the drawing. It now records the files it writes (name and hash) and leaves everything else alone, with one notice; deleted exports go to the Trash, and a case-only rename moves the export. Exports from earlier versions are not recorded: delete the old file once and the next save recreates it.

- **Obsidian re-import into the vault.** The destination folder is chosen before anything is written: if it already holds files, the import goes to a fresh "<Vault> (import N)" folder, so links never point at an older import (also with a partial overlap).
- **Low-memory canvas.** Settings shows a "Restart now" button while the saved value differs from the running one; new command `app.restart` ("Restart Vaultdraw").
- **Table paste and Favourites safety.** With `on_paste = "always"` a table over the limits is now pasted as text instead of being swallowed; pastes over 256,000 characters are no longer parsed (a huge CSV no longer throws). Favourites no longer saves after a failed read (which could wipe the list) and no longer writes a change into another vault after a vault switch.

- **Libraries and profiles.** Deleting the same library twice in one second keeps both recoverable copies; renaming a library never replaces a file that appeared meanwhile. A profile copy that fails leaves no half-made profile, and deleting a profile moves it to `profiles/.removed/` instead of erasing it. The AI (MCP) server now caps one input line.

## [0.2.0] - 2026-10-28

The plugin platform, Markdown notes with Obsidian vaults, Linux builds and memory work. See [RELEASE-NOTES.md](RELEASE-NOTES.md).

### New

- **A clearer name-clash message.** Renaming or moving onto a name that differs only in capitals or accents now says which file is in the way ("A file named 'été.excalidraw' already exists here (names that differ only in capitals or accents count as the same)"), and dragging in the tree refuses that drop before you let go, with the same Unicode-aware comparison as the backend.
- **A drawing locked while it is open switches to view mode.** If a save is refused because the file became read-only, the drawing shows the read-only banner (now saying how to fix it in Finder) with **Save a copy**, and your edits stay in the window. The quit dialog offers **Save a copy…** for such a drawing.
- **Quit and vault switch ask the same way about unsaved notes.** With `notes.autosave_ms = 0`, switching vault now asks (Save and Switch / Don't Save / Cancel) like quit does, and both dialogs name the notes. A note that cannot be saved stops the switch before your drawing closes, with a message naming it. At quit, every save (drawing, notes, library, plugin data) runs on its own, so one failure no longer skips the others, and Discard and Close names only what failed.
- **A startup notice for plugins waiting for review.** When an enabled plugin is off until you review it (never confirmed, or an update added a permission), one toast at launch names it with a **Review** button that opens Settings, Plugins. The same notice names plugin folders refused for reusing an official plugin id. After this update, plugins you added yourself ask once before their first run (the confirmation record did not exist before). A damaged `plugin-consent.json` is now moved aside as `plugin-consent.json.corrupt` and the notice says so, instead of silently holding everything. Once per launch; the plugin row now says it stays off until reviewed.
- **Linux: no more silent loss of file watching.** When a big vault passes the system's inotify watch limit (`fs.inotify.max_user_watches`), Vaultdraw now polls the vault instead of running with no watcher, and shows one notice on open that says how to raise the limit. `files.watch_poll_ms` (default 5000, 500 to 600000) sets the interval and is only read if the fallback is needed. macOS is unchanged. See [Large vaults on Linux](docs/configuration.md#large-vaults-on-linux).
- **Read-only drawing files open in view mode.** A drawing whose file has no write permission (or is Locked in Finder) opens read-only with a banner, "Read-only file: make it writable to edit", and a **Save a copy** button (the same `file.saveCopy` command), instead of letting you edit and then refusing the save. The open already knows: the native read marks the file, at no extra cost. Make it writable and the banner and view mode lift by themselves.
- **Low-memory canvas (opt-in).** `memory.low_memory_canvas = true` (Settings, Interface, Memory) backs the editor canvases with CPU memory: with three small drawings open the packaged app peaks at about 360 MB instead of about 470 MB, at the price of panning at about 60 frames per second instead of about 120. Off by default; read when the editor starts, so restart after changing it. Also adds `perf/run.mjs --owner-typical` (the simultaneous whole-app memory peak). See [Memory](docs/configuration.md#memory).
- **Vault backup and restore.** `Vault: Back up vault…` (also Settings, General, Backup) writes `<vault> backup <date>.zip` of your drawings, notes and attachments (optionally the vault's settings and history) to a folder you pick: streamed in the background with progress and Cancel, and verified by re-reading the zip and comparing a SHA-256 per file. `Vault: Restore from backup…` extracts into a new folder only, then offers to open it as a vault. `[backup] every = "daily"|"weekly"`, `folder`, `keep` schedule it and prune only the backups this feature made (off by default, no thread until on). CLI: `vaultdraw backup [--to <dir>]`, `vaultdraw restore <zip> <dir>`, no app needed. See [Backups](docs/configuration.md#backups).
- **Several libraries (library management).** Every `.excalidrawlib` file is its own section in the library panel: `libraries/` in the config folder, `.excalidraw-vault/libraries/` in a vault, and any folder in `[library] folders`. Fold sections, create, rename and remove libraries (remove keeps the file in a `.removed` folder), move items between them and import a file into a chosen one. The existing `library.excalidrawlib` stays as **Personal**, no migration. `[library] default` picks where new items go. Palette: `Library: New library`, `Library: Rename <name>`, `Library: Remove <name>`, `Library: Import file into <name>`; `Insert: <item>` searches every library. Files changed outside the app reload live. See [Library](docs/configuration.md#library).
- **Vaults in iCloud Drive, Dropbox, Syncthing or OneDrive.** Conflict copies (`name (conflicted copy …)`, `name.sync-conflict-…`, iCloud's `name 2`) show in the file tree with a `conflict` badge (`sync.conflict_badge`); the row menu's **Compare with original…** and the commands `sync.compareWithConflictCopy`, `sync.keepThis`, `sync.keepOther` open the two versions side by side and keep one: the other goes to the file's History and the copy to the Trash, never deleted. iCloud files that are not downloaded yet (`.name.excalidraw.icloud`) show as `not downloaded` instead of being read as empty; a click asks iCloud to fetch them (`sync.download_placeholders`). Temporary and partial files (`~$x`, `x.tmp`, `.syncthing.*`, `x.sb-…`) stay out of the tree, the search index and the watcher. See [Sync services](docs/configuration.md#sync-services).
- **Frames and presenting (official plugin).** A Frames panel lists a drawing's frames in slide order (drag or `Alt+Up` / `Alt+Down` to reorder, `F2` to rename, click to zoom; the order is kept on the frames in the file, so it still opens in Excalidraw). Present (`Mod+Alt+P`) shows each frame as a slide, full screen with the chrome hidden like focus mode: arrows, `Space` and `PageDown` move, `L` is the laser pointer, `Esc` ends, dots at the bottom show progress. Every command is rebindable; `[plugin.frames]` sets `transition` (`none` or `fade`), `background` and `show_progress`. Plugin API 0.28.0 adds `ctx.present`, `ctx.scene.fitTo` and frame names. Off with `plugins.disabled = ["frames"]`; unused it costs nothing.
- **Fix: opening an official plugin's panel first.** The Favourites (and Frames) activity bar button now starts the plugin host when the panel is opened before any plugin command ran; before, the panel stayed empty.
- **Focus mode: `view.focusMode`, Esc to leave.** One toggle (Cmd/Ctrl+Shift+Enter, the editor's main menu, the palette) hides everything but the canvas and the drawing toolbar. `[focus] hide` picks the parts (the new `status_bar` is one), `remember` reopens in focus mode, `hint` shows a small `Focus` chip. Esc (`view.focusMode.exit`) leaves it. `layout.preset.focus` keeps working but lost its default key. See [Layout and focus mode](docs/configuration.md#layout-and-focus-mode).
- **Table (official plugin).** Paste spreadsheet cells, CSV or a Markdown table and a toast offers **Insert as table** (`[plugin.table] on_paste = "ask"`, `"always"` or `"never"`); the palette command **Insert table from clipboard** does it from the clipboard. The table is an ordinary group of rectangles, lines and text, in your current stroke and font, columns sized to content with wrapping at `max_col_width`. Plugin API 0.28.0: `ctx.clipboard` (`readText`, `onPaste`; permission `clipboard`; activation `onPaste`), `ctx.scene.currentTextStyle()` and toast action buttons.
- **Favourites (official plugin).** Bookmark drawings, notes and single elements from the file tree or tab menu, `Mod+Alt+J`, or the palette; a side panel lists them in your order (drag or `Alt+Up` / `Alt+Down` to reorder, `F2` to rename, `Delete` to remove); `favourites.open1` to `open9` jump to the first nine. Stored per vault in the `[favourites]` table of `settings.toml` (plain TOML) and kept in step with renames, moves and deletes, also those made before the plugin first loaded in the session. Off with `plugins.disabled = ["favourites"]`; off or unused it costs nothing.
- **Auto-export (official plugin, off until you turn it on).** `[plugin.auto-export] enabled = true` (Settings, Plugins, Auto-export) writes an SVG and/or PNG copy of a drawing after each save, next to it or into an export folder that mirrors your folders (`formats`, `scale`, `background`, `theme`, `folder`). Exports are debounced and rendered one at a time in idle time, never inside the save; they follow a rename (`on_rename`) and a delete (`on_delete`); a folder list (`exclude`) and a `#no-export` text in a drawing (`skip_tag`) opt out. Palette: `auto-export.export-all`, `auto-export.export-current`. Plugin API 0.27.0 adds `ctx.vault.exports` (`render`, `move`, `remove`; `.svg` and `.png` only, never under a dot folder). See [Auto-export](docs/configuration.md#auto-export).
- **Profiles.** A named folder of settings, keys, theme and extensions (`profiles/<name>/config.toml` and its own `overrides.toml`) layered over your `config.toml`; the default is your existing config, so nothing migrates. Switch live from the palette (`profile.switch`, `profile.new`, `profile.duplicate`, `profile.delete`), Settings, General, Profile, `vaultdraw profile list|use|new|duplicate|delete`, `vaultdraw --profile <name>` or `VAULTDRAW_PROFILE`. A vault can name its profile (`.excalidraw-vault/profile`). See [Profiles](docs/configuration.md#profiles).
- **Community plugins registry (backend).** `network.allow_plugins` (asked once, revocable), `plugins.registry_url` and `plugins.registry_ttl_hours`. The app can fetch and cache a plugins `index.json` and install a package from it: the zip must match the list's SHA-256, is read strictly (the rules of `vaultdraw-plugin check`), and its manifest id, version and permissions must match the entry. Format: `sdk/docs/registry.md`. **Settings → Plugins → Browse community plugins…** lists it with search, details and the permissions the plugin declares, and installs, updates and uninstalls (palette: `plugins.browse`, `plugins.browseRefresh`). The default list address points at `Vaultdraw/plugin-registry` (published, empty for now); set `plugins.registry_url` to use another.
- **`[extensions] history`: switch the History panel off.** Hides the panel, checkpoint dialog, History button, activity bar entry and the `history.*` commands. Saving versions stays under `history.enabled` (Settings, Extensions: "File history"), so turning the panel off never stops versions from being kept. On by default.
- **Mermaid is an official plugin.** The `mermaid` plugin owns the Mermaid on/off switch (`[extensions] mermaid` and `plugins.disabled` both work, as before); off means the dialog, the More tools and palette entries, pasting Mermaid text as a diagram and the converter chunk are all gone. New for programs and AI apps: the method `mermaid.to_drawing` (`vaultdraw plugin call mermaid to_drawing '{"text":"graph LR; A-->B","path":"diagrams/flow.excalidraw"}'`, or an AI tool while Settings > AI is on) turns Mermaid text into a new drawing, or into shapes on the drawing on screen. Plugin API 0.23.0 adds `ctx.diagrams.mermaidToElements(text)`, the editor's converter as scene ops, loaded on first use.
- **LaTeX formulas are now an official extension.** The formula code (MathJax, the insert and edit dialog) moved out of the core into the bundled `formula` plugin. Commands (`Formula: Insert formula`, `Mod+Shift+M`; `Formula: Edit formula`), double-click to edit and the `[extensions] formula` switch work as before. Existing formulas keep working: they are ordinary SVG images with their TeX under `latex`, so a drawing opens and shows them even with the extension off. Off, MathJax never loads and notes show the TeX source of `$…$` instead of the picture. An edit redraws the formula on the same element (one undo step): its id, stacking order, group and bound arrows stay.
- **Plugin API 0.24.0.** `ctx.math.render` / `ctx.math.provide` (the TeX renderer the notes view and other plugins share), `ctx.scene.selection()`, `ctx.scene.currentStrokeColor()`, and `ctx.overlays.open(component, { modal: true })` for dialogs that leave the drawing visible. See `sdk/docs/surfaces.md`.
- **PDF import is now an official extension.** It ships in the app, stays on by default and switches off in Settings, Extensions (`[extensions] pdf-import = false`): off, its command, main menu item and picker entry are gone and no code loads. Same dialog, page ranges, settings (`[pdf_import]`) and result (locked pictures, one undo step); dropped `.pdf` files up to 128 MiB still work. The command `file.importPdf` is now `pdf-import.import` (rebind a key you had set on the old id). Drawings that already hold imported pages are unaffected. The dialog now opens over the drawing area (an overlay), and the pages are added when it closes.
- **Plugin API 0.26.0: PDF and page placement.** `ctx.pdf` (permission `pdf`) opens a PDF and renders pages with the app's native renderer (PDFKit, poppler) and reads the `[pdf_import]` settings. `ctx.scene.placePages(sizes)` says where page-sized pictures go in the open drawing (page mode or a column), `ctx.scene.sizeBytes()` gives the drawing's size, and `ctx.scene.batch` takes `pageCount` (set the page count in the same undo step) and `reveal` (scroll the first added element into view). `pdf` is no longer a reserved importer extension: a plugin may import `.pdf`, and `plugins.importers` picks the winner when two do. Docs in `sdk/docs/reference.md`.
- **Plugin API 0.22.0: methods other programs can call.** A plugin declares `[[contributes.methods]]` (needs the new permission `control`) and answers with `ctx.methods.register(name, handler)`: JSON in, JSON out, a timeout, and the plugin loads on the first call. `vaultdraw plugin methods` lists them and `vaultdraw plugin call <plugin> <method> [json]` runs one; the control socket has `plugin.methods` and `plugin.call`. A method with `mcp = true` also appears as an AI tool (`<plugin>__<method>`) while Settings > AI is on and Vaultdraw is running. The test harness gets `callMethod`, and the example plugin `flow-from-text` shows two methods (Mermaid-style text to a flowchart, an element count).
- **Plugin commands from the command line.** `vaultdraw plugin commands [plugin]` lists installed plugins and what they declare (with enabled and loaded state); `vaultdraw plugin run <plugin>.<command>` runs one, loading the plugin on first use. New control methods `plugin.commands` and `plugin.run` (CLI role only).
- **Plugin API 0.20.0.** A command in `plugin.toml` can set `repeat = true` to run again while its key is held. It is used by the graph extension.
- **Plugin API 0.21.0.** `ctx.workspace.openShortcut(path)` returns the key label bound to opening a drawing (it follows the user's own bindings). The graph extension uses it for the shortcut row in its hover card.
- **Plugin API 0.19.0: a plugin's own table in the vault settings.** `ctx.vault.table.read/update` reads and changes `[<plugin id>]` in `<vault>/.excalidraw-vault/settings.toml` (comments and other tables stay). Only plugins that ship with the app may use it, so the graph extension keeps its `[graph]` table as it is today.
- **Copy the AI app setup.** The palette command `AI: Copy the AI app setup (MCP server config)` (`ai.copyMcpSetup`) copies the `mcpServers` entry for `vaultdraw mcp`. `vaultdraw mcp` now also answers JSON-RPC batches, survives a line that is not UTF-8, keeps answering `ping` while a tool call is slow, and reads a modern client's name from each request.
- **Plugin API 0.18.0: the vault graph as bytes.** `ctx.vault.graph.read()` returns the whole link graph in one binary call, and `graph.layout.load/save` keeps a graph view's layout per vault. Needs `vault.read` (and `vault.write` to save). New native command `plugin_call_raw` carries bytes with the same allowlist, permission and consent checks as `plugin_call`, so a graph of 50k notes does not go through JSON.
- **Plugin API 0.20.0: thumbnails and folders.** `ctx.thumbnails` (hooks over the app's one thumbnail service, no extra memory) and `ctx.workspace.useFolder` (sorted, live folder entries) for plugin views that show drawings. Docs in `sdk/docs/surfaces.md`.
- **The Gallery is now an official extension.** It ships in the app, stays on by default and switches off in Settings, Extensions: off, its activity bar button, commands and code are gone and it costs nothing. Same grid, keys and thumbnails (they still come from the app's one thumbnail service). Commands `thumbnails.galleryToggle` and `thumbnails.galleryOpen` are now `gallery.toggle` and `gallery.show-folder`; a saved config list that does not name `gallery` in `plugins.enabled` needs it added. Plugin commands can now declare `repeat = true` in `plugin.toml` (run again while the key is held).

Nothing to declare and nothing loaded until one opens. Example `overlay-demo`, docs in `sdk/docs/surfaces.md`.

The docs include a copyable Vim-style example.
- Settings → Hotkeys has a **Key group names** section for `[keys.labels]`: add, rename or remove the names which-key shows for a group. The config writer now handles the nested `[keys.labels]` table and quoted sequence keys such as `"<leader> f f"`, keeping your comments and order. Existing configs keep working.
- A which-key popup lists what can follow a half-typed sequence. It loads only when a sequence is used. **Keys: show which-key** and **Keys: cancel pending sequence** are in the palette.
- Settings → Hotkeys has a **Sequence** button that records a sequence chord by chord. A key that is the start of another command's sequence shows a `prefix` warning.
- The tool keys (`R`, `E`, `A`, `Q` and the rest) are now commands, `tool.rectangle`, `tool.eraser` and so on, with the same default keys. They can be rebound, removed or turned into sequences in Settings → Hotkeys or `[hotkeys]`.
- `vaultdraw export` no longer sends the image through the control channel as base64. The app writes it to a spool file in 4 MiB pieces and the command moves it to the destination, so big exports no longer hit the 32 MiB limit and the command itself stays at a few MB of memory (32 MiB export: 95 MB -> 3 MB peak). The no-overwrite rule is unchanged.
- **Settings → Plugins** lists installed plugins. You can turn each one on or off, install one from a folder, reload or uninstall it, and edit the settings it declares. Each plugin shows its activation time and a memory estimate. A plugin that isn't bundled asks for consent before it runs.
- **Plugin safe mode:** after two launches in a row crash with plugins enabled, the next launch loads no plugins and says why. Holding Option at launch does the same. The palette commands **Plugins: Restart in safe mode** and **Restart normally** switch between the two.
- **Dev reload:** a plugin with `dev = true` in its `plugin.toml` reloads when its files change.
- Palette commands: **Plugins: Open plugin settings**, **Install from folder…** and **Reload plugin list**.
- New palette command **Plugins: Open plugins folder** (`plugins.openFolder`) shows the plugins folder in your file manager.
- Only the first 6 plugin panel buttons show in the activity bar. The palette or Settings → Interface shows the others.
- A plugin can declare `permissions` in `plugin.toml` (`vault.read`, `vault.write`). The enable dialog lists them in plain words, and the app remembers what you confirmed. An update that adds a write permission is switched off until you press **Review** in Settings → Plugins; an added read permission loads with a notice. A permission is a declaration, not a sandbox: plugins still run with full access. See `sdk/docs/permissions.md`.
- Plugin API 0.9.0: an arrow in `scene.batch` can bind to an element already on the canvas with `start`/`end: { id }` (a rectangle, ellipse, diamond, image or free text), as well as to one added in the same batch with `{ ref }`. The arrow is drawn between the outlines and bound as if you had drawn it, so moving the shape moves the arrow; one undo removes the arrow and both bindings. `vaultdraw scene apply` and the AI tools' `edit_drawing` share the same rules, so they accept `{ id }` too. See `sdk/docs/reference.md`.
- Plugin API 0.8.0: `ctx.markdown.parse` (the app's Markdown parser: a note's blocks, links, tags and stats), `ctx.text` (`measure` and `lineHeight`, the editor's text widths), `ctx.fonts.ensure` (load fonts before measuring) and `ctx.pages` (`geometry` and `flow`, page sizes and pagination). CodeMirror 6 (`@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/commands`, `@lezer/common` and `@lezer/highlight`) is shared with plugins and loads on first import. See `sdk/docs/reference.md`.
- Plugin API 0.7.0: `scene.batch` (and importer results) can add images: `{ type: "image", width, height, image: { mime, bytes } }`. Pictures are hashed (SHA-1) and stored once; a batch that would take the drawing past 90% of its 32 MiB cap is refused with `TOO_LARGE`. Arrows cannot bind to images. See `sdk/docs/reference.md`.
- Plugin API 0.6.0: `ctx.vault` lists folders (`list`), reads drawings (`readDrawing`), creates drawings (`createDrawing`, create only) and shows the vault's name and read-only state (`info`). Reading needs `vault.read`, creating needs `vault.write`. See `sdk/docs/reference.md`.
- Plugin API 0.6.0: `ctx.workspace` opens a drawing (`open`, optionally in a new tab) and gives the open drawing's path (`activePath`). Both are free.
- Plugin API 0.6.0: plugins can import file types. `[[contributes.importers]]` in `plugin.toml` declares them, and `ctx.importers.register` handles them. The plugin loads only when a matching file is dropped on a drawing or picked in **Import: File…**. An import is one undo step. See `sdk/docs/importers.md`.
- Plugin API 0.6.0: `onDrop:<ext>` activation loads a plugin when a file with a declared extension arrives. It adds nothing an importer does not already do.
- Plugin API 0.6.0: the `vault.changed` event reports vault files that changed on disk, as vault-relative paths with a `rescan` flag. It needs `vault.read`.

- Plugin API 0.4.0: the `group` op groups ids or `{ ref }` members (at least two). A label is grouped with its container. `createDrawing` takes groups and refs too.
- Plugin API 0.4.0: plugin data on elements (`data`, at most 4 KiB as JSON) is stored under the key `data_key` in `plugin.toml`, default `plugins.<id>`. Read it with `scene.dataOf(id)` or `scene.get(ids, { data: true })`. `ctx.manifest.dataKey` gives the key.
- Plugin API 0.4.0: `scene.get(ids, options)` returns more detail (groups, frame, label container, style, link, lock; points and data on request). `scene.dataOf(id)` and `scene.path()` are new.
- Plugin API 0.4.0: `scene.batch(ops, { path })` applies only if that drawing is still active; otherwise it refuses with `DRAWING_CHANGED`.

- Plugin API 0.4.0: scene refusals carry a `code`: `NOT_FOUND`, `READ_ONLY`, `DRAWING_CHANGED` or `INVALID_ARGUMENT`. Plugins can check `ctx.host.has("scene.path")` for the 0.4.0 batch additions.

- `sdk/examples/flow-diagram` is an example plugin: a panel button and a command insert a connected flow (boxes, bound arrows, one group) in one undo step.
- **Import: Cancel** (`plugins.cancelImport`) stops a running plugin import. It has no default shortcut and can be rebound in `[hotkeys]`.
- **Import: File…** accepts the file types that plugins import, as well as PDFs and images.

### Security

- **Plugin ids and the list address.** A new plugin cannot take the name of a built-in command group (`vault`, `file`, `view`, `config`, …) as its id, so its commands cannot look built in; plugins already installed under such a name keep working. The native side now reads `plugins.registry_url` itself when it fetches the community list, instead of trusting the address the page sends.
- **Links run only link-callable commands.** `vaultdraw://cmd` links now use an allow list (view and appearance toggles, zoom, focus mode, Settings, back and forward, new drawing, open a drawing) instead of a list of blocked words, so a newly added command is never reachable from a link by default. List an exact id in `control.uri_allow` to make another reachable from a link. A command always asks first, even when listed, and the old block list stays as a second check. The refusal message no longer tells people to edit `uri_allow`. See [Control](docs/configuration.md#control).
- **Plugins: no official ids, and first run always asks.** A community or folder-installed plugin can no longer reuse an official plugin's id (`graph`, `gallery`, `table`, …): the install and the scan refuse it (only a plugin with `dev = true` may stand in for one while you develop). A user plugin that was never confirmed now needs a review before it loads, even when it declares no permission, so a shared profile or config that lists it in `plugins.enabled` cannot switch it on silently; the Settings row says "Needs review" and Review records your answer. Plugins you already confirmed keep working; a plugin you enabled earlier that declared no permission asks once.

### Faster

- The search indexer lists each folder with one bulk directory read on macOS, the same read the file tree uses, instead of one file-system query per drawing: listing 3,000 drawings took about 20% less time in a unit benchmark. A drawing removed while a folder is being listed no longer matters: that folder is listed again one entry at a time.
- Opening a vault shows the file tree sooner on a slow CPU: the home pane now draws one frame after the tree, in the same place (about 10 ms sooner at 4x CPU slowdown). `interface.defer_home_pane = false` draws both together.
- `vaultdraw search` and the first in-app search on a vault with no index are faster on a 5,000-drawing vault: about 240 ms instead of 360 ms at background priority and 10 to 17% faster at normal priority, with 20 to 30% less CPU. The indexer now reads each drawing only up to its elements instead of the whole file with its embedded images, opens files relative to their folder, and reads on up to 8 threads. The index is still stored outside your vault and is still safe to delete.
- Switching between drawings is faster on a slow CPU: the editor now shows the new drawing in one render instead of two. On a 4x-throttled CPU, switching back and forth takes 6 to 12% less time (median) and 11% less at the slow end (95th percentile).
- Opening a vault is a few milliseconds faster on a slow CPU: adding the vault to the recent list no longer makes the settings be parsed and checked a second time.
- `interface.thumbnail_max_elements` in `config.toml` sets the biggest drawing that gets a thumbnail (default 8000, was a fixed 2,500). Changing it applies live.
- **Start file list** (Settings → General → Startup, `files.list_start`, default when idle): the walk of every vault folder that feeds Recent drawings, the file switcher, link suggestions and the move dialog no longer runs at vault open. The file tree still loads at once. "On first use" waits for the first of those.
- **Startup** settings (Settings → General): choose when the search index, link index and file history start: on open, when idle, or on first use (`search.start`, `links.start`, `history.start` in `config.toml`, live reload). Search and links default to when idle, so opening a vault no longer waits for indexing; history stays on open so every edit is versioned.

### Fixed

- **Quitting no longer loses note text.** Cmd+Q, closing the window and switching vault now write every open note first. With `notes.autosave_ms = 0` they ask: Save and Close, Don't Save or Cancel.
- **Typing while a drawing is renamed or moved.** Saves wait for the rename or move and then use the new path, so there is no false "Drawing changed on disk" and saving keeps going.
- **Notes: a folder renamed or deleted outside the app** (Finder, git) now updates the `[[link]]` index at once (that folder is re-walked alone), and a burst of changed notes lists each parent folder once.
- **Importing the same Obsidian vault again** goes into a fresh folder (`<Vault> (import 2)`), so its links point at its own drawings and not at the first import's.
- Repeated failed saves of a drawing (a locked file, a full disk, a sync tool holding it) keep one recovery copy per drawing instead of one per retry, so the recovery store no longer fills up and blocks every save with "Recovery storage is full". A successful save removes it, and the recovery list skips an oversized record instead of failing.
- Saving no longer replaces a drawing you made read-only (or Finder-locked): the save is refused with a read-only message. A normal save keeps the file's permissions and its extended attributes (Finder tags, colour labels).
- Creating drawings and notes works on exFAT and FAT drives (no hard links): the exclusive no-replace rename is used instead, and an existing file is still never overwritten.
- Renaming or moving a drawing onto a name that differs only by accent case or Unicode form (`Été` and `été`, composed and decomposed `é`) no longer replaces the other file silently: it is refused as a name clash, and the file system's own no-replace rename guards every move. Case-only renames of the same file (`notes` to `Notes`) now work.
- **Fix: profiles and a vault's profile.** The profile you chose yourself is now saved in `state.json` while a vault's profile is active, so after a restart a vault with no profile goes back to your choice. **Fix: presentation keys.** Binding `Frames: Next slide` to a canvas tool key (such as `N`) no longer shows a conflict, and the key advances the slide: a running presentation counts as modal, so tool keys stand down.
- **Tabs and note links after a reload or a new note.** A restored background tab whose file was deleted outside the app is now marked missing (as an open tab is) instead of being dropped. A note you create, rename or delete is added to or removed from the `[[link]]` index at once (own actions and the file watcher); the full note rescan keeps its 10 s limit and no work runs before a note is first opened.
- **Renamed command ids no longer break your keys.** A key bound in `[hotkeys]` to an old id (`thumbnails.galleryToggle`, `thumbnails.galleryOpen`, `file.importPdf`) keeps working, and so do those ids in the palette history, the CLI, `command.run` and links; they resolve to `gallery.toggle`, `gallery.show-folder` and `pdf-import.import` when they run, even if the extension registers later. See "Renamed commands" in `docs/configuration.md`.
- **Editing a formula or a plugin shape keeps the element.** Both used to replace the image (new id, top of the stacking order, group and bound arrows lost). Plugin API 0.25.0: a scene `update` can carry `image` to change an image's picture in place, as one undo step, with the plugin's existing scene write permission. `ctx.shapes.update` and the formula edit use it.
- **Formulas in `rgb()` / `hsl()` colours** keep their colour instead of turning near-black.
- **Official plugins stay on after an upgrade.** Official plugins (markdown-import, gallery, later the graph) are on unless you turn one off: Settings writes the ones you switched off to `plugins.disabled`, and `plugins.enabled` keeps your own plugins. A saved `plugins.enabled` that predates an official plugin no longer hides it; every official plugin is on after an upgrade, because none shipped in a release before this (markdown-import first ships in 0.2.0). "Restore defaults" on the Extensions page turns every official plugin back on.
- An arrow or line no longer shows at the top-left corner (scene 0,0) while you drag it and jumps into place on release: the preview is now drawn where you started. A new end-to-end spec (`shapesMatrix`) draws every shape tool in every stroke style, width, roughness, fill, edge and arrowhead and checks it while dragging, after saving and reopening, in dark mode, zoomed, and in the SVG export.
- Library: an edit to `library.excalidrawlib` made outside the app now shows up live when your config folder is reached through a symlink (stowed dotfiles, a linked folder). The change event arrived under the real path and was dropped.
- `vaultdraw launch --safe` reaching an app whose window is still starting is no longer lost, and is asked only once. A normal restart no longer edits the app's own environment while it exits; the new process just starts without `VAULTDRAW_SAFE`.
- `control.uri_enabled` and `control.uri_allow` are now read through every config layer (included files, `config.toml`, `overrides.toml`), like `control.enabled`. Before, links read only `config.toml`, so turning links off from Settings or with `vaultdraw config set` did nothing. A broken `overrides.toml` now turns links off, as it does AI.
- Renaming a tag across the vault no longer shows an extra "Updated N links" message next to "Renamed #a to #b" when the rewrite finishes very fast.
- Drawings with more than 600 elements now get a thumbnail in the gallery, home, search and palette (up to 8,000 elements). Parsing, restoring, measuring and painting each run in short steps, so the app stays responsive while thumbnails draw.
- The activity bar disappears when every entry is hidden, instead of leaving an empty 36 px strip. Showing one entry again (Settings → Interface) brings it back.
- A plugin with `dev = true` is no longer switched off for good after three errors. It stops for the session, the disable is not saved, and the next save reloads it with a fresh error count.
- Dev reload now also works for plugins in symlinked folders and in temp folders on macOS (watched paths are canonicalised).
- An app started with both `VAULTDRAW_VAULT` and `VAULTDRAW_STATE_DIR` set opens only that vault and no longer reads or writes your own `recent-vault` (used by `dev --sandbox`; nothing changes when either variable is unset).

- A save reads the drawing once instead of twice when it is older than 100 ms and its file stamp (inode, size, modification time) is unchanged; any doubt falls back to the full second hash. About 3 ms less per save of an 8.6 MB drawing.

- Backlinks panel with backlinks, outgoing links and unlinked mentions.
- Renaming or moving a drawing updates the links that point to it, and a notice reports what changed.
- Drawing shortcuts: give any drawing its own key.
- Graph view of every drawing and link, plus a local graph of the drawings near the open one, with search and filters.
- Tags: a Tags panel, tag chips in the file tree, a tag filter in search, `#` autocomplete, and renaming a tag across the whole vault.

**Themes and appearance**

- Colour themes for the app and the drawing board, each with light and dark variants, plus Light, Dark and System modes.
- Built-in themes including Dracula, Tokyo Night, Catppuccin, Everforest, Gruvbox, Nord, Rosé Pine and Solarized.
- Themes use the Noctalia palette format, so existing Noctalia palettes work; add your own as JSON files in the config folder.
- Sync canvas with theme: recolours the on-screen canvas to match the theme, while saved files and exports keep standard colours.
- Accent colour that replaces the theme's primary colour, adjusted for contrast when needed.
- Whole-app interface zoom from 50 to 200 percent.

**Settings and hotkeys**

- Settings page with sections and search, in the style of Obsidian.
- Plain-text configuration in `config.toml` in a config folder (`~/.config/vaultdraw` on macOS and Linux), edited by hand or in Settings, and reloaded live.
- Comments in `config.toml` are kept when you change a setting in Settings.
- Typos never break the app: the last good settings stay in use and a banner names the line that failed.
- Per-vault settings in `.excalidraw-vault/settings.toml`, with a Global / This vault switch for each setting.
- Hotkeys page to view, add, change and reset the key for every command, with conflict warnings and a key recorder.

**Command palette**

- Cmd/Ctrl+P opens a drawing by name; Cmd/Ctrl+Shift+P runs any command.
- Fuzzy matching, so `vdg` finds `vault-design`; recently used items come first.
- Every feature is a palette command, including themes, modes, settings pages, export, templates and insert actions.
- Tab narrows to a family of commands, and Cmd/Ctrl+Enter runs a command without closing the palette.

**Plugins (experimental)**

- Plugin host for drawing panels and commands from folders in the config folder, enabled through `config.toml`.
- A plugin that crashes is switched off and reported, without affecting the rest of the app.

**Command line `vaultdraw`**

- Install the `vaultdraw` command from the command palette, into your PATH or into `/usr/local/bin`.
- Offline commands to list, read, search, write, create and move drawings, and to show links, tags and settings.
- Commands for a running app: open a drawing and wait for it, list and run app commands, switch tabs, and quit.
- Shell completions and a manual page; `vaultdraw --help` lists everything.

**History and recovery**

- File history keeps earlier versions of each drawing, including versions saved before an outside change or a command-line write.
- History panel with a timeline, previews, thumbnails and highlights of what changed since a version.
- Restore a version as a copy, export it as `.excalidraw`, or create named checkpoints.
- History settings control how many versions are kept and when old ones are cleared.
- Delete a drawing's history, or exclude it from git when the vault is a git repository.

### Improved

- Faster startup and vault opening; features such as settings, history, graph, PDF import and formulas load only when you first use them.
- Lower memory use: caches are cleared when macOS reports memory pressure or when the app has been hidden for a while, and closed editors release their canvas memory.
- Large vaults stay responsive: the search index and link index build in the background, and long folder lists scroll smoothly.
- Saving and opening large drawings is faster on Apple Silicon.
- Smooth zooming and panning, with frames drawn at the display's refresh rate (up to 120 Hz on ProMotion displays).
- The command palette and Settings open instantly, even in large vaults.
- Tab switching is smooth, and switching back to a tab restores its undo history.
- Designed to run well on low-end Macs, with idle drawings using little memory and background work kept small.

### Fixed

- A vault stays writable after the window reloads; if a vault is read-only, the reason is shown and you can try again.
- Moving, renaming or trashing an open folder no longer shows it as missing.
- Undo no longer reaches back into a previous drawing after switching to another one.
- Pen colours and opacity no longer leak into the next tool.
- Text created by double-click or paste takes the Text tool's style.
- Dark-mode SVG images show their colours correctly on macOS.
- Library previews show formulas and images in the on-screen colours.
- Page 1 in page mode sits below the floating toolbar.
- Right-click Reload menu is hidden in release builds, while text fields keep their normal menu.
- The Ctrl-based save, settings and search shortcuts keep working on macOS.

### Known limitations

- The build is unsigned, so the first open needs **right-click → Open** or **System Settings → Privacy & Security → Open Anyway** (see the README).
- Memory: with a typical vault the app peaks around 420 MB while opening drawings (the goal is under 400 MB). Idle use is about 215 MB. Bringing the peak down is the focus of the next release.
- macOS only for now. Windows and Linux builds are not part of this release.
- Plugins are experimental and their interface may change.
- There is no automatic update yet. Check the [GitHub releases](https://github.com/Vaultdraw/vaultdraw/releases) page for new versions.
